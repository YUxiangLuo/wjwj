## 2. Findings

### P1：1024px 主路径被遮挡，却被记为非阻塞 OBS

**标准**：高风险清单第 4 节要求在 1024px 桌面宽度下关键按钮和正文不被遮挡；第 6 节进一步明确，辅助卡片可横向滚动，但正文和提交主路径被遮挡属于阻断问题。

**证据**：

- `test-results/checklists/run-6.md` 记录文档宽度为 1280px、横向溢出 256px，底部主操作“继续：撰写报告”的右边缘约为 x=1248，必须横向滚动才能触达。
- `test-results/checklists/i-series-analysis-1024.png` 中结果表右侧和主操作区域均被视口裁切。
- `test-results/checklists/summary.md` 却将其归为 OBS-18，并列入“不阻塞，供产品取舍”。

**影响**：结果页的正文和阶段推进操作在清单明确要求支持的宽度下不可直接访问，不满足高风险清单的退出标准。

**建议**：将该项改判为 P1/FAIL；让结果页在小于 1280px 时回流为单列，或由负责人书面接受风险并注明期限。修复后应重新截取 1024×800 的完整页面，并断言页面无文档级横向溢出、主操作完整可见且可聚焦。

### P1：ST-S06 是 S0 项，但三种分层分配算法没有直接验证

**标准**：ST-S06 要求使用非对称层规模和层内标准差，分别手算核对比例、等额、奈曼分配，并验证容量约束后的剩余名额仍按正确目标重新分配。统计清单退出标准要求 S0 为 0 个失败。

**证据**：

- `test-results/checklists/summary.md` 的覆盖表将 S01–S10 整组列为已覆盖。
- 同一报告随后承认 ST-S06 未直接执行，只验证了“各层之和等于目标 n、每层范围合法、单单位层和层内普查”。
- `batch-*.json` 中没有 ST-S06 的原始断言。

**影响**：当前证据只能证明分配结果满足容量约束，不能发现“比例、等额或奈曼公式算错，但输出仍满足总和和上下界”的实现错误。因此不能关闭该 S0 门禁。

**建议**：增加至少一组非对称夹具，使三种算法给出不同答案；独立手算每层目标，覆盖某层达到容量上限后剩余名额重新分配。将结果保存为可复算的原始断言。ST-A07 的“超过 20 类及真实类别名‘其他’”也未直接执行，但其级别为 S1，可单独登记风险。

### P2：汇总计数与原始断言不一致

**证据**：

1. `summary.md` 各批 PASS 相加为 308，不是总计行声明的 310。
2. 12 个 `batch-*.json` 共 306 PASS；加上 `verify-t07.json` 的 2 PASS，仍为 308。

**影响**：无法由原始数据稳定复算总报告；原始失败被标绿也会降低后续审计和回归比较的可信度。

**建议**：保留首次执行为 FAIL，再追加带提交版本和时间的复验 PASS，不要改写历史结果；由脚本从 JSON 生成汇总计数，并为浏览器观察生成独立结构化断言。按现有材料，正确计数应至少改为 308 PASS、15 OBS、0 个未关闭 FAIL，同时单独列出历史 FAIL→复验 PASS。

## 3. 逐提交结论

### `e8b0469` — `fix(student): map the worker source mismatch to a 409 source conflict`

- `saved-analysis-service.ts` 只捕获 `WorkerServiceError` 且要求错误码精确为 `SOURCE_MISMATCH`，随后转换为 `AnalysisConflict(SOURCE_CONFLICT, 409)`。
- 超时、繁忙、工作线程崩溃和其他分析错误仍按原路径传播，没有被误报为来源冲突。
- 新增真实数据库回归覆盖“请求前替换总体字节”，并断言返回 409 且不写入分析记录。
- 结论：改动正确，未发现阻塞问题。

### `a4b2aa9` — `fix(server): reject control characters in template names`

- 检查发生在 `decodeURIComponent` 之后，因此 `%00` 与直接 NUL 都会被识别。
- 检查发生在 `resolve`、`Bun.file` 之前，避免底层路径 API 抛错形成 500。
- 非法名称沿现有路由返回 404，合法模板行为不变。
- 结论：改动正确，未发现阻塞问题。

### `2f4d4f8` — `docs(checklist): record that numeric columns need declared missing codes`

- 两份清单均说明数值列空单元格会在映射阶段被拒绝，测试缺失值应使用字典声明的缺失码。
- 说明保留了 `sampleCount=5 / validCount=4 / missingCount=1` 和 `0` 为有效值的统计合同。
