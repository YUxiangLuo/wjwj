# 三轮深度 Dogfood 测试规划

本规划面向**当前 HEAD 的完整项目**（学生端、教师端、管理端、统计引擎、数据与文件、部署边界），以人工/半自动探索为主，攻击自动化测试的盲区。专题规则的唯一事实来源仍是 [教学指南](TEACHING.md)、[课题模型](../RESEARCH_MODEL.md)、[运行与部署](OPERATIONS.md)、[数据库操作](../DATABASE.md)、[安全边界](../SECURITY.md) 与[设计系统](../DESIGN_SYSTEM.md)；本规划不重复这些规则，只定义**怎么测、测什么边界、怎么判定通过**。

## 2. 方法与判定

- **工具**：agent-browser（真实浏览器、截图、键盘、网络拦截/限速）、`curl`（HTTP 头/权限/边界）、`psql`（数据库断言）、`scripts/benchmark-analysis.ts`（容量）、`bun test`（修复后回归）。
- **证据**：每轮报告 `test-results/dogfood-3r/round-N.md`（gitignored，含场景 ID、复现步骤、预期/实际、截图路径、SQL 断言、关联自动化建议）；截图只保留有判别力的状态并逐张查看。
- **严重级别**：P0 统计错误、越权、错误来源、数据污染或重复写入；P1 可恢复性、完整功能边界、资源限制；P2 扩展压力、体验；P3 文案/展示。P2/P3 不得替代 P0/P1。
- **纪律**：只用合成/种子数据；不 reset 应用库；API 可做夹具与结果核对，但 UI 断言必须由真实浏览器操作产生；发现 P0 立即记录并暂停该方向，先补最小修复与自动化回归，再重跑该轮相关场景；不把预期 409/403 当异常。
- **轮次准入**：每轮结束必须 `bun run verify`、`bun run test:db`、`bun run test:teaching` 全绿；新发现的缺陷必须先落一条自动化回归。

**已知非缺陷（上一轮深度测试结论，勿重复上报）**：截止前受理、写锁中跨截止仍落库的 admit-once 语义；1024px 下“随手查结果”辅助卡片裁切；R7 分位数与 PPS 边界 ≤2e-16 浮点误差；随机顺序套件偶发时序抖动。

## 6. 覆盖对齐（与既有自动化测试的边界）

| 区域 | 自动化已覆盖 | Dogfood 重点 |
| --- | --- | --- |
| 变量字典/分析契约 | `bun run test:unit`、`test:db`（A/R/D/Q 系列） | 真实浏览器下的极端数据与多窗口组合 |
| 并发与实库 | `test:db` 竞争矩阵 | 进程级故障、网络断连、恢复演练 |
| 教学主链路 | `test:teaching` 14 项 PASS | 反向路径、边界值、破坏性操作、容量 |
| 样式与无障碍 | `check:styles` + axe 关键页 | 键盘完成关键任务、窄屏、长内容 |
| 安全 | 审查 + 权限集成测试 | 头部/代理/上传签名/路径穿越的真实请求 |

## 7. 每轮交付与退出标准

1. 报告：环境与 commit、场景逐项结果（通过/失败/阻塞）、复现步骤、证据路径、DB/SQL 断言、自动化回归建议。
2. 门槛：P0 为 0；P1 全部修复或写明接受理由；P2/P3 记录不阻塞。
3. 回归：所有新修复合入自动化（优先扩展现有测试文件），并重跑 `verify`、`test:db`、`test:teaching`。
4. 清理：删除临时库/工作目录/失败截图以外的一次性产物；保留可复现反例。
