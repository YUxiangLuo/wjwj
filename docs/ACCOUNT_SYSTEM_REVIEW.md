# 账号体系 Review（班级管理 / 用户导入）

范围：学生与教师账号的创建、导入、删除、班级归属，以及班级/学期的生命周期。
动机：历史上出现过「软删除导致学生永远无法重新导入」，本轮对该类问题做系统排查、修复、回归测试，并按产品决策移除低频功能。

## 1. 数据模型与硬约束

| 实体 | 关键约束 | 含义 |
| --- | --- | --- |
| `student` | `student_id` **citext UNIQUE（全表）**，`class_id` NOT NULL | 学号全局唯一，一个学生同时只属于一个班级 |
| `teacher` | `employee_id` citext UNIQUE | 管理员可删除**无班级、无实验模板**的教师（有引用时 409）；删除会一并清理该教师作为操作者的审计记录（隐私取舍，仅保留 `teacher.deleted` 脱敏留痕） |
| `class` | 硬删除；有学生或任务时拒绝 | 班级可被管理员删除 |
| `semester` | 当前学期不可删；有班级时拒绝 | — |
| `experiment.student_id` | `ON DELETE CASCADE` | 硬删学生会级联删除实验/提交/成绩/抽样记录 |

关键推论：**学号全局唯一且行不会随"禁用"消失**。任何"按学号查重"的逻辑一旦忽略账号状态，就会把停用账号变成永久死锁——这正是历史缺陷的根因。

## 2. 历史沿革（含 git 证据）

- `2398724`：导入带「复活」分支，条件为 `deletedAt IS NOT NULL`（软删除时代）。`toggle_status` 只翻 `status`、从不写 `deletedAt`，因此**停用账号当时也无法被导入复活**。
- `47f225e Replace soft deletes with hard deletes`：`DELETE` 改为真正删行（学号释放，"删除→重导入"被修好），同时删掉了已经无用的复活分支；但 `status` 列与「禁用/启用」按钮保留了下来 → **停用路径依旧死锁**。
- `24e121c`：为仍然存在的 `status` 补回原地复活语义（本文件 3.1）。
- 本轮（移除低频功能）：**删除账号停用/启用**，于是"状态忽略"这一整类缺陷从根上消失；后续短暂上线过的管理员调班能力也已移除（见 R3）。

## 3. 已修复（保留在最终实现中）

### 3.1 导入/新增按账号归属分类（`src/teacher/routes/classroom.ts`）
| 情况 | 行为 |
| --- | --- |
| 不存在 | 新建（密码=学号），计入 `successCount` |
| 本班已存在 | 跳过不改写，计入 `skippedCount`（不再算失败） |
| 其他班 + 同教师 | 失败：`学号已存在于班级「X」，如需变更班级请先在该班级删除该学生` |
| 其他教师 | 失败：`学号已被其他教师使用`（不泄露班级名） |
| 并发重复 | 导入改为 `ON CONFLICT (student_id) DO NOTHING … RETURNING`：并发抢号方逐行落为「跳过」或「指名班级」错误，两个请求都返回 200（不再依赖 409 兜底） |

### 3.2 其他
- 班级删除失败提示具体原因（几名学生、几个任务）。
- 班级创建/改名要求教师存在；班级归属创建后不可变更。
- 导入结果新增 `skippedCount`/`skipped`，前端分别展示"新建 / 已存在跳过 / 失败"。

## 4. 已移除（本轮，按产品决策）

| 功能 | 移除内容 | 语义后果 |
| --- | --- | --- |
| A 学生账号停用/启用 | `student.status` 列+索引+check、教师端与管理员端入口、登录状态校验、各处 `status = 1` 过滤 | 学生只有"存在"一种状态；移除学生只能硬删除（级联清空实验/成绩），无"保留数据的临时禁用" |
| B 教师账号停用/启用 | `teacher.status` 列+索引+check、管理员入口、教师登录状态校验 | 教师账号一旦创建即长期有效，只能用重置密码/删除（管理员本就没有删除接口） |
| C 管理员更换授课教师 | `PUT /api/admin/classes/:id` 的 `teacherId` 分支、编辑对话框教师选择、移交并发测试 | 班级归属不可变更；建班时必须选对教师，选错只能删除重建（有学生/任务时不可删） |

迁移 `drizzle/postgresql/0001_friendly_mother_askani.sql`：仅删除上述两列及约束/索引，**不删除任何账号行**；因此迁移前处于"停用"状态的账号会变为正常可用账号（如需清理，请显式删除）。

同步更新：`src/db/seeds/default.ts`（移除 T004「停用教师」/S019「停用学生」，教师 3 / 学生 15）、`check-default.ts`（A 任务未开始 2 人）、README 账号表与计数、SECURITY.md 四条停用相关安全性质、DATABASE.md 并发说明、`src/lib/api-client.ts` 的 `ACCOUNT_DISABLED`。

## 5. 测试覆盖

- 单元/路由：1061 条（1052 pass / 9 skip / 0 fail）。含新增的导入分类（跳过、跨班提示、跨教师不泄露班级名）、班级列表计数、班级删除原因。
- 真实数据库：`bun run test:db` 11 条，含 `re-importing an active roster row neither duplicates nor rewrites the account`（真实"新增→重导入"只保留一行、不改名改密）、`hard deleting a student requires confirming the cascaded submissions`、`a class keeps its teacher: reassignment is not a supported write path`。
- 浏览器实测：教师端学生名单无启停用入口、管理员教师列表无状态列、班级编辑对话框教师只读、删除确认框列出将被级联的实验与成绩条数。
