# 教师端专项 Dogfood 测试计划

本文面向 `/teacher` 的专项验收，目标是在真实浏览器、真实 Cookie、真实 PostgreSQL 和独立 storage 中，发现自动化测试难以覆盖的教师工作流、跨资源一致性、破坏性操作、并发冲突与可理解性问题。

它与[全面深度 Dogfood 测试计划](DOGFOOD_TEST_PLAN.md)互补：全面计划验证三端及统计系统，本计划只聚焦教师端，并把教师操作对学生实验、冻结提交和成绩导出的影响作为端到端判定依据。通用统计数值边界仍以[统计学专业验收清单](STATISTICAL_TEST_CHECKLIST.md)为准，避免在两份文档维护不同答案。

## 1. 结论与优先级

教师端最值得优先测试的不是静态页面，而是以下五条跨模块不变量：

1. **对象级所有权**：教师只能读取和操作自己班级、模板、任务、学生与提交，不能通过改 URL、查询参数或下载地址跨教师访问。
2. **模板冻结**：发布后冻结总体、字段、研究合同、变量字典、抽样策略和评分权重；首次分配后再冻结名称、描述、推荐题和附件。修改只能通过复制新模板完成。
3. **来源一致性**：总体文件、字段映射、可选字典的 source/revision、抽样结果和提交快照必须来自同一版本；文件缺失或哈希变化时必须 fail closed。
4. **评分状态一致性**：评分、驳回和学生重提以实验 version 串行化；状态、分数、评语、驳回原因、审计记录与冻结权重必须匹配。
5. **破坏性操作完整性**：删除学生、任务和未分配模板前准确展示影响；确认后数据库级联、会话撤销和文件清理一致，取消或失败时不得部分删除。

建议按 T0–T8 九轮执行。时间紧张时，至少执行 T0、T2、T3、T5、T6 中涉及 S0 风险的项目；完整专项建议安排 1–2 个工作日，并由一名熟悉系统的测试者和一名首次使用的教师共同完成 T1/T3/T5。

## 2. 系统分析

### 2.1 教师端边界

教师 SPA 有六个一级工作区：教学概览、班级管理、实验模板、实验任务、作业批改、成绩分析与导出。浏览器通过同源 `teacherApi` 调用 `/api/teacher/**`，所有非登录接口统一经过教师会话鉴权。

```diagram
┌──────────────┐     ┌─────────────────┐     ┌──────────────────┐
│ Teacher SPA  │────▶│ /api/teacher/** │────▶│ Auth + ownership │
└──────┬───────┘     └─────────────────┘     └────────┬─────────┘
       │                                               │
       │                 ┌─────────────────────────────┼──────────────┐
       │                 ▼                             ▼              ▼
       │          ┌────────────┐                ┌────────────┐ ┌───────────┐
       └─────────▶│ Topic/task │                │ Grading    │ │ Classroom │
                  │ services   │                │ snapshot   │ │ roster    │
                  └─────┬──────┘                └─────┬──────┘ └─────┬─────┘
                        └──────────────┬───────────────┴──────────────┘
                                       ▼
                              ┌─────────────────┐
                              │ PostgreSQL + FS │
                              └─────────────────┘
```

关键所有权文件：

- 页面与导航：`src/teacher/TeacherApp.tsx`；
- API 路由表：`src/teacher/api.ts`；
- 课题、任务、附件：`src/teacher/routes/topic-task.ts` 与 `src/teacher/topic/**`；
- 班级和学生：`src/teacher/routes/classroom.ts`；
- 批改与冻结材料：`src/teacher/routes/grading.ts`；
- 成绩分析和 Excel：`src/teacher/routes/export.ts`；
- 会话：`src/teacher/routes/auth.ts` 与 `src/server/user-session.ts`。

### 2.2 教师主状态机

```diagram
┌──────────┐   上传总体   ┌──────────┐   映射/合同/可选字典/策略/权重   ┌──────────┐
│ 新建草稿 │────────────▶│ 配置草稿 │━━━━━━━━━━━━━━━━━━━━━━━━━━━━▶│ 可发布   │
└──────────┘             └────┬─────┘                            └────┬─────┘
                              │ 替换总体                              │ 发布
                              ▼                                       ▼
                         配置失效重做                           ┌────────────┐
                                                              │ 已发布模板 │
                                                              └─────┬──────┘
                                                                    │ 分配班级
                                                                    ▼
                                                            ┌──────────────┐
                                                            │ 活动实验任务 │
                                                            └──────┬───────┘
                                                                   │ 学生提交
                                                                   ▼
                                                  ┌──────────┬──────────┬──────────┐
                                                  │ 待批改   │ 已驳回   │ 已评分   │
                                                  └──────────┴──────────┴──────────┘
```

发布和分配不是同一动作：发布后学生仍看不到模板；必须分配到班级才产生任务。删除任务会永久删除该任务下的实验、成绩和抽样记录。模板有任务后不能删除，也不能通过 API 绕过冻结。

### 2.3 当前自动化覆盖

当前 `src/teacher` 有 48 个测试文件，其中 26 个路由测试、8 个页面/组件测试，其余为 topic 服务和纯逻辑测试。优势包括：

- 路由输入验证、所有权过滤、发布门禁、附件类型、CSV 编码和删除确认；
- 字典 revision、映射/发布/换源竞态、任务唯一性、截止时间单调延期；
- 评分/驳回 version CAS、冻结快照、样本导出、成绩分析和 Excel 数值类型；
- PostgreSQL 并发、跨教师权限和 storage mutation lock；
- 教学浏览器闭环已覆盖模板复制、字典保存、任务发布、冻结附录、驳回、重提、评分、Excel 和双窗口字典冲突。

专项 Dogfood 应补足以下缺口，而不是重复逐条单元测试：

- 从空白模板开始，完全通过 UI 走完七步配置，而非大量依赖 API 设置；
- Dashboard、班级列表、任务进度、批改列表、批量导出的真实筛选/返回/失败恢复；
- 名册导入的编码确认、部分成功报告、错误文件下载和跨班占用解释；
- 两名不同教师的真实会话与下载越权，而不只是同一教师两个窗口；
- 删除预览到最终级联的数据库和 storage 核对；
- 1024×768、200% 缩放、键盘操作、慢网、断网和重试；
- 10k/100k 总体、500 人名册、大量任务和提交时的教师页面容量。

## 3. 测试治理

### 3.1 严重度

| 级别 | 教师端定义 | 发布要求 |
| --- | --- | --- |
| S0 | 越权；错误评分/导出；冻结材料污染；发布不完整模板；不可恢复的数据或文件损坏 | 0 个未解决 |
| S1 | 主流程不可完成；冲突后丢输入；删除影响错误；任务/进度数量错误；生产或容量明显失效 | 必须修复，或明确风险接受人与期限 |
| S2 | 可访问性、文案、布局、非关键筛选或恢复体验问题 | 有记录、有负责人 |

发现问题时记录实际影响，不根据 HTTP 5xx 自动定级。一个清晰、可恢复且无写副作用的失败，与静默写入错误数据的严重度不同。

### 3.2 环境

- 独立、已迁移、可丢弃 PostgreSQL 数据库；
- 独立 storage 根目录，不与开发或生产文件混用；
- `DEV_AUTH_MODE=0`，通过真实 Cookie 登录；
- 固定 `TZ=Asia/Shanghai`，记录数据库和系统时钟；
- 开发服务器用于定位问题，T7 必须再用普通生产构建复验；
- 浏览器至少 Chromium；视口覆盖 1440×900、1024×768、200% 缩放；
- 开发者工具保留网络日志、控制台错误和下载文件。

### 3.3 账号与业务夹具

| 夹具 | 用途 |
| --- | --- |
| 教师 A | 拥有 A1/A2 两个班、多个模板和任务 |
| 教师 B | 拥有 B1 班和独立模板，用于跨教师越权 |
| A1 学生 4 名 | 未开始、进行中、已提交、已评分各一名 |
| A2 学生 2 名 | 跨班、任务重复发布和名册占用 |
| B1 学生 2 名 | 跨教师对象和下载权限 |
| 同教师窗口 A/B | 字典、发布、评分和删除并发 |
| 不同教师窗口 A/B | 所有权与会话隔离 |

模板至少准备：

1. 数值均值模板：含标识符、目标数值、PPS 规模、2–4 个分层；
2. 类别比例模板：含全角/半角类别、缺失编码和 21 个类别截断边界；
3. 最简模板：无字典、无附件、PPS/分层禁用；
4. 文件模板：含 PDF/图片/文档附件和推荐题；
5. 边界模板：10k 与 100k 行总体；
6. 已发布未分配、已发布已分配、草稿三种状态。

名册夹具包括 UTF-8、GBK/GB18030、前导零、文件内重复、跨班已存在、全角/大小写变体、空字段、非法邮箱、500/501 行。

### 3.4 每个案例的证据

每个 S0/S1 案例至少保存：

- 代码版本、服务器配置、账号与夹具 ID；
- 操作前后的页面截图；
- 关键请求的方法、URL、状态码、错误码和响应摘要；
- 对应数据库行的状态/version/revision/计数；
- 涉及文件时保存路径、大小、哈希和 storage audit；
- 并发案例记录两个请求的开始/完成顺序；
- 导出案例保存原文件及独立解析结果。

证据目录建议为 `test-results/teacher-dogfood-YYYY-MM-DD/<run-id>/`，最终生成 `REPORT.md`、`manifest.txt` 与 `checksums.sha256`。

## 4. T0：基线与测试资格

### 目标

排除环境、迁移、seed 或已知测试失败，建立后续案例的可信起点。

### 步骤

- [ ] 记录 commit、Bun 版本、PostgreSQL 版本、系统时间、时区和环境变量白名单；
- [ ] 对独立数据库执行迁移、seed 和 seed check；
- [ ] 运行 `bun run verify`、`bun run test:db`、`bun run test:teaching`、`bun run test:unit:random`；
- [ ] 执行 `bun run storage:audit`，确认起点无孤立文件；
- [ ] 教师 A/B、学生和错误角色分别真实登录；
- [ ] 对六个教师一级页面和四个深链执行刷新，确认均可恢复；
- [ ] 保存数据库行数、storage 清单与首页截图作为基线。

### 退出标准

自动化门禁为绿；DB 测试不能以 skip 代替；两个教师账号的所有权夹具明确；浏览器无阻断控制台错误。

## 7. T3：实验模板七步配置专项

这是教师端风险最高、人工投入最多的一轮。

### A. 空白 UI 主链

完全通过浏览器完成，不使用 API 代替页面步骤：

1. 新建名称与描述；
2. 上传总体并核对列、行数和预览；
3. 配置标识符、数值、分层、其他字段与研究合同；
4. 可选：确认变量字典、标签、单位、类型、类别顺序和缺失编码；
5. 配置抽样策略；
6. 编辑推荐题并上传教学附件；
7. 配置评分权重、保存并发布。

| ID | 操作 | 通过标准 |
| --- | --- | --- |
| TD-301 | 完整走通带字典的数值均值模板 | 步骤状态、保存值和发布后详情一致；刷新或重开向导不丢已保存内容 |
| TD-302 | 完整走通类别比例模板 | 目标类别、NFKC 规范化、字典类别与研究问题一致；目标类别在图表截断时保留 |
| TD-302A | 最简模板不创建变量字典，直接完成其余步骤并发布 | 发布成功；字典保持为空；学生端和后续提交不依赖虚构的字典版本 |
| TD-303 | 在每一步尝试跳过、返回、关闭、刷新 | 未保存内容有明确行为；已保存内容不被旧页面覆盖；不能跳过发布门禁 |
| TD-304 | 使用浏览器后退、Escape、点击遮罩和重复保存 | 对话框焦点/关闭语义一致；重复动作不产生重复附件或 revision |

### B. 总体文件和映射

| ID | 操作 | 通过标准 |
| --- | --- | --- |
| TD-305 | 0 字节、损坏 XLSX、改后缀、重复/空列名、50/51 列、100000/100001 行 | 仅允许边界内文件；失败不更新课题、不留下孤立文件 |
| TD-306 | 上传同名新文件、替换不同列结构的文件 | 新字节原子替换；旧映射/策略/字典按规则失效；UI 不继续展示可发布状态 |
| TD-307 | 标识符含空值、规范化重复；数值含缺失/非数值/常量/不可靠尺度 | 在保存或发布前给出具体行和字段；不能静默转 0 或默认方差 |
| TD-308 | 分层 1/2/20/21 类、空层；PPS 规模含 0/负数/缺失 | 角色与策略门禁符合模型；不可行配置不落库 |
| TD-309 | 研究合同留空、手写问题、切换目标后返回 | 必填项逐项提示；系统默认问题只在未手写时更新，不覆盖教师文本 |

### C. 变量字典

| ID | 操作 | 通过标准 |
| --- | --- | --- |
| TD-310 | 文本 `"01"`、`"1"`、数字 `1`、false、0、null | 字典原始编码保持不同；标签可相同但绑定值不混淆 |
| TD-311 | 缺失编码输入非法 JSON、重复、与类别冲突 | 输入保留，revision 不变，错误指出原因 |
| TD-312 | 两窗口基于同一 revision 保存不同标签 | 仅一个成功；败者保留输入并提供重新载入；重试 revision 单调增加 |
| TD-313 | 保存字典同时替换总体、改映射、发布模板 | 最终只允许同一 source/revision 的完整组合，不发生冻结后补写 |
| TD-314 | 200/201 类别边界、把高基数字段改连续 | 边界和提示正确；连续解释要求所有非缺失值可解析 |

### D. 策略、附件、推荐题与权重

| ID | 操作 | 通过标准 |
| --- | --- | --- |
| TD-315 | 只启用一种方法、必做 PPS 无规模列、必做分层无分层字段 | 页面和 API 均拒绝；失败不改变原策略 |
| TD-316 | 上传合法 PDF/图片/文档，并测试伪造签名、SVG、双扩展、大小 ±1B、超长中文名 | 类型由扩展和签名共同约束；路径安全；失败无孤立文件 |
| TD-317 | 附件预览/下载/删除，另一模板仍引用同一文件 | Content-Type/Disposition 正确；删除不误删仍被引用的文件 |
| TD-318 | 推荐题 0/30/31 条、重复 ID、脚本富文本 | 边界正确；危险内容在教师与学生所有入口都不执行 |
| TD-319 | 权重边界、总和 99/100/101、小数与字符串 | 页面/API 规则一致；无效输入不保存；合法权重在提交快照和总分中一致 |

### E. 发布、冻结、复制和删除

| ID | 操作 | 通过标准 |
| --- | --- | --- |
| TD-320 | 分别缺总体、映射、合同、策略、权重时发布；另用与当前总体冲突的字典 source/revision 发布 | 每个门禁或版本冲突独立指出原因；状态仍为草稿；未配置字典本身不阻止发布 |
| TD-321 | 发布后直接 UI/API 修改总体、字段、字典、策略和权重 | 全部拒绝且内容不变；允许的查看行为仍正常 |
| TD-322 | 首次分配后修改名称、描述、推荐题和附件 | 进一步冻结生效；UI 明确引导复制模板 |
| TD-323 | 复制草稿、已发布和已分配模板 | 副本属于当前教师、状态为草稿、资源独立；后续修改任一模板不影响另一份 |
| TD-324 | 复制与总体替换/附件删除并发 | 副本来自一个一致时点；文件复制失败时事务与文件都回滚 |
| TD-325 | 删除草稿并取消/确认；删除已有任务模板 | 取消零写入；草稿数据库与文件清理一致；已有任务模板稳定拒绝 |

## 8. T4：任务发布、截止时间与进度

| ID | 操作 | 通过标准 |
| --- | --- | --- |
| TD-401 | 发布模板到一个/多个班级 | 每班一个任务；开放时间由服务端确定；学生立即可见；未选模板/班级时不发请求 |
| TD-402 | 对同一模板和班级重复发布、快速双击、两个窗口并发发布 | 已有班级禁用；唯一约束兜底；不重复任务，响应能解释跳过结果 |
| TD-403 | 教师 A 尝试把模板发到教师 B 班级，或发教师 B 模板 | 拒绝且不泄露目标是否存在 |
| TD-404 | 截止时间测试过去、当前、未来、无效格式与 UTC+8 显示 | 仅合法未来时间保存；显示与服务端判定一致 |
| TD-405 | 延期到更晚、相同、更早时间；两窗口并发延期 | 只允许单调延长；旧窗口不能覆盖新值；最终时间唯一 |
| TD-406 | 核对进度页所有状态、搜索/筛选和 PPS 不适用提示 | 每个学生恰落入一个状态；数量与实验表一致；PPS 提示只出现于真实不可用学生 |
| TD-407 | 学生提交、驳回、重提、评分时保持进度页打开 | 刷新后状态正确；旧状态不被错误缓存；批改入口只对可批改项出现 |
| TD-408 | 删除无实验、进行中、已提交、已评分任务 | 预览计数准确；高影响删除需确认；确认后级联完整，重新发布得到全新空任务 |
| TD-409 | 删除预览与新提交并发；两个窗口同时删除 | 事务重新核对；只有一个删除成功；无半份审计或孤立记录 |

## 9. T5：批改、驳回、冻结证据与导出

### A. 批改列表和详情

| ID | 操作 | 通过标准 |
| --- | --- | --- |
| TD-501 | 状态筛选、分页、搜索后进入详情并返回 | 返回后查询参数保持；总数和列表一致；跨页无重复/遗漏 |
| TD-502 | 查看包含四种抽样、字典、题目关联和 10 条分析引用的提交 | 页面显示的是冻结快照；与学生提交页和数据库 snapshot 一致 |
| TD-503 | 提交后修改当前模板/字典/总体，再重开详情 | 仍显示冻结内容；总体哈希不符时明确 fail closed，不能用当前文件重建旧样本 |
| TD-504 | 完整样本导出 simple/systematic/PPS/stratified/all | 行数、列、索引、前导零和内容与冻结结果一致；无公式注入 |
| TD-505 | 缺失总体、篡改 source hash、截断 sampling JSONB | 返回明确来源/存储错误；不能显示空结果或继续评分 |

### B. 评分与驳回

| ID | 操作 | 通过标准 |
| --- | --- | --- |
| TD-506 | 分项 −1/0/100/101、空、非数字、小数，评语边界 | 仅合法值通过；字段错误具体；总分由冻结权重独立计算 |
| TD-507 | 点击评分后取消，再确认；快速双击确认 | 取消零写入；确认只有一次 version 推进和一条审计；按钮防重复 |
| TD-508 | 驳回原因空值/边界，取消后确认 | 原因规则正确；驳回后分数/评语不残留；学生看到准确原因 |
| TD-509 | 驳回→学生修改→重提→评分 | 新快照自洽；旧快照不回填；教师可清楚识别当前版本 |
| TD-510 | 两窗口评分不同分数；评分与驳回并发；重提与评分并发 | 仅一个合法状态获胜；败者提示冲突并保留输入，不自动覆盖 |
| TD-511 | 教师 B 读取/评分/驳回/下载教师 A 提交 | 全部拒绝，无状态、分数、审计或下载副作用 |

### C. 成绩分析与导出

| --- | --- | --- |

| TD-513 | 未开始、进行中、待批改、已驳回、已评分混合 | 人次口径清晰；成绩分布和分项均值只统计应统计的已评分记录 |
| TD-514 | 单项导出与多选批量导出，重复点击和取消下载 | 文件数量、命名、内容正确；失败项可定位；不重复生成错误文件 |
| TD-515 | 用独立工具解析 Excel | 头行即使空结果也存在；分数是数值单元格；冻结姓名/模板名正确；公式前缀已防护 |
| TD-516 | 教师 B 构造教师 A taskId/classId/topicId | 过滤与导出均不能泄露行数、姓名、分数或文件 |

## 10. T6：鉴权、会话、并发与故障注入

### A. 会话和对象权限

| ID | 操作 | 通过标准 |
| --- | --- | --- |
| TD-601 | 未登录、学生 Cookie、管理员 Cookie 调用所有教师 API 类型 | 稳定 401/403/404，无对象存在性或内部错误泄露 |
| TD-602 | 遍历替换 topic/task/class/student/experiment/attachment ID | 读取、写入、预览、下载全部按所有权拒绝 |
| TD-603 | 同浏览器先登录教师 A，再登录教师 B，旧标签继续操作 | 旧页身份 pin 检测变化并停止写入；不能串号 |
| TD-604 | 教师改密后测试当前/其他 Cookie 和旧/新密码 | 当前会话按规则旋转；其他旧会话失效；密码与会话原子更新 |
| TD-605 | 退出请求断网、正常退出、退出与重新登录并发 | 失败明确提示尚未安全退出；旧退出响应不能清除新会话 |
| TD-606 | 写接口缺 Content-Type、跨站 Origin/Referer/Sec-Fetch、重复身份参数 | 全部无副作用拒绝 |

### B. 并发矩阵

用两个独立浏览器会话或两个数据库连接执行，并核对最终状态：

- [ ] 字典保存 ↔ 字典保存；
- [ ] 字典/映射/总体替换 ↔ 发布；
- [ ] 发布 ↔ 首次任务分配；
- [ ] 附件删除 ↔ 模板复制；
- [ ] 学生导入 ↔ 学生删除；
- [ ] 任务延期 ↔ 任务删除；
- [ ] 评分 ↔ 驳回；
- [ ] 学生重提 ↔ 教师评分；
- [ ] 成绩导出 ↔ 任务/学生删除。

每组必须得到一个可解释的串行结果，不接受“两个请求都 200”但最终状态依赖时序的情况。

### C. 故障注入

| ID | 操作 | 通过标准 |
| --- | --- | --- |
| TD-607 | 页面加载、保存、上传、发布、评分时断网 | 明确区分未发送、可能已提交和服务端拒绝；输入保留；刷新可核对最终状态 |
| TD-608 | 终止数据库连接后读取和写入，再恢复 | 请求快速失败或重连；页面可重试；进程不崩溃，无半写 |
| TD-609 | storage 只读、写失败、删除失败 | DB 引用与文件保持一致；错误可恢复；storage audit 无新增孤立文件 |
| TD-610 | 上传或导出请求中途取消、浏览器关闭 | 临时资源清理；再次操作成功；不留下不可见锁或重复文件 |
| TD-611 | 慢网下快速切换页面、筛选和对象 | 旧响应不覆盖新状态；加载提示可感知；操作按钮只锁定必要范围 |

## 11. T7：可访问性、容量与生产候选

### A. 可访问性和布局

- [ ] 仅用键盘完成登录、名册导入、七步向导、任务发布、评分确认和批量导出；
- [ ] 焦点始终可见；对话框关闭回到触发器；模态背景不可 Tab 到；
- [ ] 错误不只靠颜色，字段错误与修复方式可被读出；
- [ ] 保存、上传、发布、评分、导出等异步状态使用可感知的 status/alert；
- [ ] 1024×768 和 200% 缩放下，主按钮、表格操作、向导底栏与确认文案可达；
- [ ] 长中文、英文、emoji、RTL 文本不覆盖状态与危险操作；
- [ ] 宽表格只在容器内滚动，页面正文不产生非预期横向滚动。

每个一级页面至少保存默认、空、加载、错误、长内容和打开对话框中的代表性截图，并人工检查。

### B. 容量阶梯

| 数据规模 | 操作 | 记录 |
| --- | --- | --- |
| 500 名学生 | 名册导入、搜索、分页、删除预览 | 耗时、错误报告、内存、最终行数 |
| 100 个模板 | 列表搜索、复制、状态筛选 | 首屏、交互延迟、请求数量 |
| 200 个任务 | Dashboard、任务列表、进度页 | p50/p95、分页/筛选正确性 |
| 1000 个提交 | 批改列表、状态筛选、成绩分析 | SQL/接口耗时、页面响应、计数 |
| 10k/100k 总体 | 上传、映射预览、复制、详情、冻结样本导出 | Worker 隔离、RSS、超时、普通读取可用性 |

不以“最终完成”作为容量通过标准。至少记录机器配置、样本数、p50/p95/max、峰值 RSS、事件循环可用性和负载后恢复。

### C. 生产候选

- [ ] `bun run start` 后检查六个一级页面和深链刷新；
- [ ] 普通生产包无演示凭据、开发鉴权或 HMR；
- [ ] 登录、API、附件和 Excel 响应头符合安全文档；
- [ ] 生产环境执行跨教师 API 和下载回归；
- [ ] 同时备份数据库和 storage，恢复后核对模板、附件、任务、提交快照和成绩导出；
- [ ] 运行 `bun run storage:audit`，确认恢复前后引用数与文件数一致。

## 12. T8：修复回归与发布彩排

每个确认缺陷先保留最小反例，再执行：

1. 缺陷最小反例；
2. 同模块相邻边界；
3. 受影响的教师 UI 主链；
4. 跨教师权限和失败副作用；
5. `bun run verify`；
6. 全新已迁移数据库上的 `bun run test:db`；
7. `bun run test:teaching` 和固定 seed 随机顺序；
8. 普通生产构建中的教师主链、批改和导出抽查。

修复 UI 外观时必须重新截图并人工检查；修复交互或语义时至少执行 DOM/可访问性检查。不得只重跑最初失败的一条测试。

## 14. 最终退出标准

专项判定为 PASS 必须同时满足：

- 所有 S0 通过，无待确认的统计、权限、冻结、评分或数据完整性问题；
- S1 全部通过，或有具名风险接受人、影响范围、缓解措施和修复期限；
- 两名不同教师的对象级权限矩阵通过；
- 空白 UI 七步模板主链、任务发布、提交冻结、驳回重提、评分和导出完整通过；
- 删除学生/任务/模板的预览、取消、确认和并发路径通过；
- 新缺陷有最小反例和能区分正确/错误实现的自动化回归；
- `verify`、真实数据库、教学浏览器和随机顺序均通过；
- storage audit 无孤立文件，临时数据库、进程和测试文件已清理；
- 报告明确列出未执行项目，不能把“未测”写成“通过”。

最终报告至少包含：总体判定、S0/S1/S2 列表、各轮结果、环境与夹具、性能数据、数据库/storage 核对、代表性截图、未执行项目、风险接受和修复后回归结果。
