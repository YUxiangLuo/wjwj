## 8. 真正验证并发、取消与权限

### 数据库竞争矩阵（P0）

使用两个独立数据库连接、显式事务屏障和 `pg_blocking_pids` 证明实际等待；不能用固定 sleep 猜测先后。对下列每一对操作分别强制两种先后顺序：

| 并发操作 | 必须成立的不变量 |
| --- | --- |
| 字典保存 ↔ 字典保存 | 不同内容同观察版本只有一个成功；败者不覆盖，不多增 revision |
| 字典保存 ↔ 发布/分配 | 先冻结则编辑失败；先编辑则发布/分配使用完整新字典；绝无冻结后补写 |
| 字典保存 ↔ 换源/改字段解释 | 保存的 source 始终对应当前来源；不能保存旧字典后误标为有效 |
| 复制 ↔ 字典保存/换源 | 副本具有同一时点可验证的源和字典，或明确无有效字典；不混合新旧状态 |
| 分析保存 ↔ 分析保存 | 同身份单记录；19 条下两个新身份只能新增一条；不同实验互不误去重 |
| 分析最终写入 ↔ 上游重开/提交 | 锁后复核，失效任务不入库；版本、代次和状态一致 |
| 提交快照 ↔ 报告保存/上游重开 | 不出现跨版本引用和证据，也不产生半份快照 |

每例同时核对响应和提交后的 DB 状态：行数、ID、version、revision、generation、引用和 snapshot 内容；注入校验后/写入前异常验证事务回滚。竞态用例先确定性通过，再重复执行至少 20 次排查偶发死锁，并设置测试超时及连接清理。

### Worker 到持久化的失败链路（P1，其中重复写入按 P0）

- 占住一个运行任务，排入 16 个不同任务，再加入一个：运行并发不超过 1，超限有明确错误，无静默丢弃；释放后 FIFO/实际约定的调度行为可观察，队列恢复。
- 以可控 Worker 验证超时含排队，覆盖排队取消、运行取消、Worker 抛错、崩溃和服务 close；再用真实 Worker 验证一次生产 30 秒超时与恢复，不能只证明 Fake Worker 正常。
- 相同 key 两个调用者，其中一个断开，不应错误取消仍被另一个等待的计算；所有等待者取消后不泄漏资源。失败结果不得持久化。
- 模拟“已提交数据库但响应丢失”，相同 requestId 重试必须返回原 ID；另测“计算完成但未提交时进程中断”，重试可恢复且最终最多一条。不要假设所有断网请求都没有副作用。
- 排队/计算跨过任务截止时刻、期间源文件被替换：最后写入仍需合法。此处是待验证风险，不将当前实现行为直接当作正确答案。

### HTTP 权限与输入攻击（P0）

用真实 Cookie/路由覆盖未登录、错误角色、同班其他学生、跨班学生、其他教师；至少各检查字典 GET/PUT、分析 GET/POST、报告保存、提交、学生详情及教师批改详情。断言无可用数据泄露且无数据库副作用，不只测试 service 的 studentId 参数。

边界包括非法路径 ID、畸形 JSON、额外可信字段、错误类型、超长研究问题（4/5/500/501 字）、过期 observedVersion、任务未开放/刚截止/已提交/已评分。未授权访问应按现行安全规则返回 401/403/404；业务冲突核对稳定错误 code，不锁死无意义的文案标点。变量标签和研究问题加入 HTML/脚本字符串，浏览器确认只呈现文本或经过既有安全清洗，不执行脚本。

## 9. 浏览器 dogfood、资源与部署检查

使用 `agent-browser` 启动独立师生会话和全新本地服务器，禁止复用已有 dogfood 数据推断成功。扩展现有教学脚本，API 可用于夹具与结果核对，不能替代待验证的 UI 操作。

1. **P0 完整链路**：复制模板→编辑并确认字典→发布分配→关联数值题并试填→完成规划与四种抽样→原始/加权分析→引用→保存并预览→提交→师生同附录→驳回重提评分。
2. **P1 冲突恢复**：两个教师窗口保存冲突；两个学生窗口产生版本冲突；失败输入不丢失，不自动合并覆盖，明确刷新后恢复。
3. **P1 请求恢复**：运行时切换标签/断网/重连/刷新；同请求不得重复保存，重载后的未保存配置行为按草稿契约检查，不额外要求跨设备同步。
4. **P0 上游失效**：保存引用后重开上游，以相同种子重抽；旧记录过期且引用清空；重新分析并引用新记录后成功提交。
5. **P1 空功能路径**：新建无字典模板完成全流程；有字典但无关联也能分析；有关联但无分析引用也能提交。既有比较分析、CSV、成绩导出各做一条回归。
6. **P1 可访问性与外观**：键盘完成字典编辑、关联对话框、数值继续和引用选择；检查对话框焦点、隐藏分析面板无 Tab 焦点、错误可感知、长标签/10 条附录/窄屏不遮挡关键操作。

截图只保留有判别力的状态：错误保留输入、切换后配置、过期记录、冻结附录及窄屏。用 `agent-browser` 截图并实际检查图像；响应、网络请求计数和 DB 断言证明行为，截图不替代断言。报告记录控制台错误和失败请求，不把预期的 409 当成未解释异常。

资源检查（P1）：对 1000、10000、100000 行及最大允许列数的合法总体记录来源解析、Worker 排队/执行、最终持锁写入耗时和峰值 RSS；并发分析时请求登录/普通读取，确认无超时、无队列越界且释放后可继续服务。记录机器配置与重复测量的 p50/p95/max；尚无产品吞吐 SLA，不凭空宣称达标。30 秒任务上限和容量上限为硬门槛，合法限额内数据若无法完成应记录实际限制并评估阻断，而非静默缩小夹具。

扩展压力（P2）：多个实验持续请求、取消、重试后比较空闲 RSS、活动 Worker、DB 连接与队列是否回落；失败应可复现，不以单次 GC 前后的内存差判泄漏。

部署检查（P1）：在空白临时 PostgreSQL 上执行当前迁移和最小 seed，验证 saved_analysis 唯一键/外键、默认 revision/generation 及删除级联；正常新建实验走通。构建后再用生产模式跑分析 Worker 和冻结读取冒烟，避免只验证 `bun --hot` 能运行。不要求旧数据格式迁移；不在应用数据库上 reset，也不借用户过去允许清库而扩大本次测试权限。
