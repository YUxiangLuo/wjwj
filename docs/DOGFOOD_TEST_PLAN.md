# 全面深度 Dogfood 测试计划

本文把项目架构、产品边界、统计模型、现有自动化和外部统计学依据整合为一套可执行的发布前 Dogfood 方案。它负责回答：**测什么、为什么测、按什么顺序测、保存什么证据、何时可以发布**。

具体统计公式与单项数值基准仍以[统计学专业验收清单](STATISTICAL_TEST_CHECKLIST.md)为事实来源；具体高风险功能项以[高风险测试检查清单](TESTER_RISK_CHECKLIST.md)为事实来源。本文不复制维护所有细项，而是把它们编排成多轮真实使用与故障演练。

> 计划基于 2026-09-19 的代码与文档审计。执行时必须记录被测 commit；若代码、迁移或专题文档变化，应先做影响分析再沿用结果。

## 1. 结论先行

这是一个面向统计学课堂的**已知有限总体抽样教学平台**，而不是通用调查分析软件。它的可信性由五条链共同决定：

1. 教师上传的总体、字段解释和研究目标正确；
2. 样本量规划、抽样设计、权重、估计量和设计标准误使用同一统计口径；
3. 学生四阶段状态、抽样代次、分析引用和提交快照来自同一版本；
4. 服务端按角色与资源归属授权，不能依赖前端隐藏；
5. PostgreSQL 记录和本地 `storage/` 文件在失败、删除、备份和恢复后仍一致。

现有质量基础较强：仓库有 200 余个测试文件、真实 PostgreSQL 集成测试、教学浏览器闭环、生产构建门禁和较完整的统计基准。Dogfood 的价值不在重复点击已有单元测试，而在于发现以下自动化难以单独证明的问题：

- 教学语义、页面文案、API 数值、导出与冻结快照是否一致；
- 多角色、多窗口、超时、重试和失败恢复是否形成合法的唯一终态；
- 极端数值、原始值类型、总体排序和缺失口径是否改变统计结论；
- 真实生产构建、代理、磁盘、数据库、Worker 和浏览器组合是否可用；
- 一个真实教师和学生是否会被界面诱导出统计学上错误的解释。

建议执行 **5 轮**，而不是一轮大而无边的回归：

| 轮次 | 主题 | 主要回答的问题 | 建议时长 |
| --- | --- | --- | --- |
| R0 | 基线与可复现环境 | 当前 commit 是否具备测试资格 | 0.5 天 |
| R1 | 真实角色与教学闭环 | 管理员、教师、学生能否完成正确工作 | 1–2 天 |
| R2 | 统计红队与独立复核 | 数值和解释是否真的正确 | 2–3 天 |
| R3 | 并发、安全与故障注入 | 错误、攻击和竞争下会不会越权或污染数据 | 2 天 |
| R4 | 生产候选、容量与恢复 | 能否在目标部署形态下安全上课和恢复 | 1–2 天 |

修复后再执行 R5 定向回归与发布彩排；R5 不是新的测试范围，而是对失败项、相邻风险项和最终主链的闭环。

## 2. 项目深度分析

### 2.1 产品与角色

| 角色 | 关键职责 | 不可接受的失败 |
| --- | --- | --- |
| 管理员 | 学期、教师、班级、学生、公告 | 组织关系错误、跨学期污染、删除影响与预览不一致、重置密码后旧会话仍有效 |
| 教师 | 总体与模板、变量字典、抽样策略、任务、批改、成绩导出 | 发布不完整模板、修改冻结材料、看到其他教师数据、评分与快照不一致 |
| 学生 | 问卷预试、样本量规划、抽样、分析报告、提交与查看成绩 | 跳阶段、旧版本覆盖、错误样本/权重/SE、提交后仍可改变冻结内容 |

系统明确只支持可信内网、桌面端、浅色主题、单实例本地文件存储。总体会被学生反复抽样并可导出完整入样行，因此只能使用合成或充分脱敏数据；Dogfood 不能把真实受限数据当夹具。

### 2.2 架构与信任边界

```text
学生 / 教师 / 管理员 React SPA
              │ 同源 API、角色 Cookie、expected user 检测
              ▼
         单一 Bun.serve
       ┌──────┼─────────┐
       │      │         │
   角色路由  统计 Worker  附件下载
       │      │         │
       └──────┼─────────┘
              ▼
      PostgreSQL + storage/
      元数据/状态    总体/附件
```

关键所有权边界：

- `src/index.ts`：三个 SPA、API 分派、安全头、静态资源和进程关闭；
- `src/student/routes/**`：学生任务、阶段、抽样、分析、提交和下载；
- `src/teacher/routes/**`：模板、任务、名册、批改和导出；
- `src/admin/**`：组织、账号与公告；
- `src/domain/statistics/**`：抽样、估计、标准误和展示分布；
- `src/domain/variables/**`：类型化变量字典和单变量分析；
- `src/db/schema.ts`：关系、唯一性、状态和检查约束；
- `src/server/storage-files.ts` 与 `attachment-download.ts`：文件路径与授权下载；
- `src/db/storage-mutation-lock.ts`：数据库—文件联合变更的串行化。

服务端是统计证据边界。客户端上传的样本行、索引、权重或纳入概率不能直接成为可信结果；分析需要从总体和已保存设计重放。Dogfood 必须直接调用 API 篡改这些字段，以证明“页面没入口”之外的服务端保证。

### 2.3 数据生命周期与一致性

```text
总体文件 ─→ 字段映射/研究目标 ─→ 变量字典 ─→ 抽样策略
   │                                              │
   └──────────── 来源标识 / SHA-256 ──────────────┘
                                                  ▼
规划 ─→ 抽样结果 + seed + indices + π ─→ 分析记录 ─→ 报告引用
                                                  │
                                                  ▼
                                    不可变提交快照 ─→ 批改/驳回
```

最重要的一致性机制是：

- 实验和字典使用 version/revision 乐观并发控制；
- 抽样、阶段 3 完成及重开上游都会推进 `samplingGeneration`；
- 已保存分析按代次和字典来源判断是否过期；
- 提交冻结问卷、规划、抽样、报告、字典、关联、分析引用和来源证据；
- 压缩样本按总体 SHA-256 恢复，文件变化时必须 fail closed；
- 文件系统和数据库不是同一事务资源，项目用 advisory lock 与补偿降低风险，但仍需真实故障和恢复演练。

### 2.4 统计能力与假设

主流程只支持完整有限总体上的单一主要目标：数值均值或明确类别比例。问卷试填不进入估计。当前不支持总量、中位数、相关/回归、假设检验、因果推断、有放回抽样，整群与多阶段只存在辅助规划而非执行设计。

#### 样本量规划

比例与均值分别使用：

```text
n₀ = z²p(1-p)/E²
n₀ = z²σ²/e²
```

之后统一按未取整的中间值执行：

```text
n_deff   = n₀ × deff
n_fpc    = n_deff × N / (N - 1 + n_deff)
n_invite = min(N, ceil(n_fpc / (1-r)))
```

其中回答率只改变邀请量，不证明无回答偏差消失。总体方差 `σ²` 使用分母 N；代码中常保存的 `S²` 使用分母 N−1，两者转换是历史高风险点。

#### 四种执行设计

| 设计 | 点估计 | 标准误口径 | 必测假设 |
| --- | --- | --- | --- |
| SRSWOR | 样本均值/0-1 均值 | 含有限总体修正 | 等概率、不放回、n=N 时 SE=0 |
| 线性系统 | 样本均值 | 枚举随机起点分段的精确设计 SD | 总体顺序和周期性会影响方差 |
| 分层 SRS | `Σ(N_h/N)ȳ_h` | 各层独立 FPC 后合成 | 层完整、不重叠；每层至少 1 个样本 |
| 不放回 πps | Hájek 比估计 | 固定 π 系统设计的随机起点精确积分 | `0<π≤1`、`Σπ=n`、必入单位 π=1 |

PPS 使用 Hájek 比估计，它可能有偏；“SE 精确”不等于“点估计无偏”或“正态区间覆盖正确”。系统和 PPS 的结果都与抽样框顺序有关。

#### 描述与单变量分析

- 未加权连续变量：均值、样本 SD、min/max、R type 7 四分位数；
- 未加权分类变量：有效值分母、保留字典中的零频类别；
- 加权分析：仅给连续变量加权均值或分类变量加权比例；
- 不提供加权 SD、加权分位数、加权 SE 或加权置信区间。

主分析图表的“代表性偏差”是各类别绝对百分点差的算术平均，不是总变差距离、假设检验、误差界或代表性证明。

### 2.5 审计后优先探针

以下不是可以忽略的理论担忧，而是代码审计发现的高价值 Dogfood 探针：

| ID | 观察 | 风险 | 本计划中的判定 |
| --- | --- | --- | --- |
| O-STAT-01 | 主分析把类别转成 NFKC 字符串；单变量字典用 JSON 类型键 | `"1"` 与 `1`、`false` 与 `"false"` 可能在两处得到不同分布 | 同一字段两处结果或口径说明不一致，记 S0 |
| O-STAT-02 | 单变量分析使用缩放与补偿求和；主分析部分均值、方差、分层和 Hájek 点估计仍用普通求和 | 大数抵消、极小数和高动态范围权重可能产生假 0、Infinity 或明显误差 | 与高精度独立基准不符且未明确拒绝，记 S0/S1 |
| O-STAT-03 | 学生 CSV 导出样本行及 PPS π/权重，不导出估计、SE、半宽 | 现有 ST-E10 无法在 CSV 层完整核对统计结果 | 不把缺失能力误报为数值失败；记录契约缺口并核对现有列 |
| O-STAT-04 | 主分析缺失值作为“（缺失值）”类别展示；字典分析从有效分母排除声明的缺失码 | 同一字段分母可能不同 | 页面没有清楚说明双轨口径时记 S1；计算违反各自契约时记 S0 |
| O-STAT-05 | “代表性偏差”除以类别数 | 增加零频类别可能让指标下降，容易被误解 | 任何“检验通过/证明代表性”文案记 S0/S1 |
| O-QA-01 | 浏览器教学闭环在完整本地 CI，不是 `pre-push` 阻断项 | 候选 commit 可能未执行真实浏览器链路 | 发布候选必须现场运行 `bun run ci:local:full`，不能借用旧结果 |
| O-OPS-01 | 无专用 readiness/指标/trace；错误主要写 stderr | 生产故障定位和趋势判断有限 | R4 强制留存代理与进程日志、延迟和 RSS；不把“无告警”当成功 |
| O-OPS-02 | 备份恢复有手册但无自动调度/恢复门禁 | 数据库与 storage 可能只恢复一半 | R4 必须完成一套独立恢复演练 |

另有一处文档漂移：统计清单 3.1 的旧实测注记称“超过 20 类未见显式聚合”，当前实现已经把图表聚合为最多 20 项并避免覆盖真实“其他”标签。执行时按当前实现与清单 ST-A07 验证，不能引用旧注记作为预期。

## 3. 外部统计学依据如何转化为测试

本节资料于 2026-09-19 通过 Web 检索并核对。外部资料定义通用统计原则；本项目特有的公式顺序、教学限制和状态语义仍以代码及仓库专题文档为准。

| 资料 | 与本项目直接相关的原则 | 转化后的测试 |
| --- | --- | --- |
| [Statistics Canada: Survey Methods and Practices](https://www150.statcan.gc.ca/n1/pub/12-587-x/12-587-x2003001-eng.pdf) | 抽样框、概率设计、分层、系统、PPS、估计与调查误差必须连贯 | 从总体、设计参数、样本、权重到估计/SE 做端到端证据追踪 |
| [UN: Designing Household Survey Samples](https://unstats.un.org/unsd/demographic/sources/surveys/handbook23june05.pdf) | deff 是复杂设计相对 SRS 的方差比；FPC 调整有限总体不放回抽样的标准误；权重必须反映设计 | 检查 deff/FPC 顺序、普查边界、PPS/分层权重与解释 |
| [Penn State STAT 506: Stratified Sampling](https://online.stat.psu.edu/stat506/Lesson06) | 分层均值按 `N_h/N` 合成；方差依设计计算；分层变量与响应无关时不保证优于 SRS | 用非比例分配手算；构造无效分层反例，禁止“分层必然更优” |
| [Penn State STAT 506: Cluster and Systematic Sampling](https://online.stat.psu.edu/stat506/Lesson07) | 方差公式必须服从实际抽样设计；不能把 SRS 公式套到系统/整群设计 | 对有序总体枚举全部随机起点；打乱顺序后确认 SE 可变化 |
| [NIST Statistical Reference Datasets](https://www.nist.gov/srd/mathematics-and-statistics) | 用带认证值的独立参考数据评估统计软件数值准确性 | 期望值必须由手算、枚举、高精度工具或独立实现产生，禁止调用被测函数自证 |
| [NIST/SEMATECH e-Handbook](https://www.itl.nist.gov/div898/handbook/dtoc.htm) | 统计方法应显式检查假设、偏差、准确度与不确定性 | 每个结论同时检查适用条件、不可用状态和页面解释，不只比最终数字 |
| [AAPOR: Response Rates](https://aapor.org/response-rates/) | 回答率与调查质量并非单调对应；高回答率不能排除无回答偏差 | 检查回答率只用于邀请量规划，UI/报告不得声称已消除偏差 |

据此，统计 Dogfood 必须同时包含四类证据：

1. **示例基准**：非对称手算数据能区分正确和常见错误公式；
2. **不变量**：索引唯一、概率和为 n、权重与行一一对应等；
3. **设计分布**：枚举随机起点或大量固定可复现重复，而非观察单次“像随机”；
4. **解释审计**：名称、单位、假设、警示和不支持范围不能夸大底层数字。

## 4. 测试治理

### 4.1 严重级别

功能风险沿用 P0/P1/P2，统计风险沿用 S0/S1/S2：

- **P0/S0，发布阻断**：错误目标、样本、权重、估计或 SE；越权；跨用户数据；错误来源；半份写入；提交快照污染；不可逆数据污染。
- **P1/S1，原则上阻断**：主流程中断、冲突丢输入、重要警示缺失、数值稳定性、恢复或容量失败。只有具名负责人、缓解措施和到期时间齐全时才可接受。
- **P2/S2，可排期**：不改变结论的显示、兼容性、可访问性或措辞问题。

发现结果与预期不一致时，先分类为“实现缺陷、文档缺陷、夹具缺陷、环境阻塞或预期产品边界”，不得为了让测试通过而放宽数值或状态断言。

### 4.2 角色分工

一人可兼任，但证据责任应分开：

| 角色 | 责任 |
| --- | --- |
| 测试负责人 | 锁定 commit/环境、分配案例、维护结果总表与退出判定 |
| 统计复核人 | 独立生成期望值，审核公式、假设、容差和解释；不得只读实现后重写同一算法 |
| 教师 Dogfooder | 按真实备课和批改习惯操作，记录易误解与高摩擦路径 |
| 学生 Dogfooder | 在没有开发者提示的情况下完成四阶段并解释结果 |
| 安全/故障测试人 | 直接 API、并发、文件和数据库故障注入 |
| 运维见证人 | 生产构建、代理、备份恢复、容量与清理 |

### 4.3 环境矩阵

| 环境 | 用途 | 必要配置 |
| --- | --- | --- |
| E0 临时自动化 | R0 门禁 | 空且已迁移的 `TEST_DATABASE_URL`，临时 storage |
| E1 功能 Dogfood | R1/R2 | `DEV_AUTH_MODE=0`，固定 `SEED_NOW`，真实登录，独立数据库/storage |
| E2 生产候选 | R3/R4 | `bun run start`，生产构建，独立域名/代理/TLS，`DEMO_MODE` 关闭 |
| E3 恢复目标 | R4 | 新空数据库、不存在的 storage 目录，与 E2 完全隔离 |

测试者本地时区可能是 Asia/Tokyo，但产品统一显示 UTC+8。边界时间案例必须记录服务器时间、原始 ISO 时间和页面显示；不能按测试机本地日期凭感觉判断。

### 4.4 账号矩阵

至少准备：

- 管理员 1 名；
- 当前教师 2 名、历史教师 1 名；
- 两个不同班级，每班至少 2 名学生；
- 同一学生的两个独立窗口，用于版本冲突；
- 同一浏览器的两个同角色账号，用于 Cookie 串号；
- 另一教师和另一班学生，用于对象级越权。

默认 Dogfood seed 已提供 3 教师、4 班、20 学生、5 课题、6 任务和多个阶段/状态，可作为基础，但每轮必须在空库 seed，并运行 `db:seed:check`；seed 非幂等。

### 4.5 证据包

每个案例至少记录：

- commit、迁移版本、Bun/PostgreSQL/浏览器/OS/代理版本；
- 构建模式与脱敏环境变量；
- 案例 ID、账号别名、夹具版本、总体 SHA-256、随机种子；
- 操作、期望、实际、HTTP 状态和业务错误码；
- 相关 version/revision/samplingGeneration/requestId；
- 关键只读数据库断言、导出文件和校验和；
- 截图、控制台、失败网络请求、server/proxy 日志；
- 性能案例的 p50/p95/max、吞吐、错误率和 RSS。

推荐目录：

```text
test-results/<candidate>/<round>/<case-id>/
  manifest.json
  steps.md
  api/
  db/
  screenshots/
  logs/
  exports/
  checksums.sha256
```

不得保存明文密码、Cookie、完整连接串或真实个人数据。现有 `test-results/` 不受 Git 跟踪，候选证据应上传到受控 artifact 或对象存储，并建立保留周期。

## 5. 数据夹具

### 5.1 基础业务夹具

使用固定 `SEED_NOW` 建立：

- 均值目标 + 可用 PPS 规模变量；
- 均值目标 + PPS 不可用；
- 比例目标 + 分层必做；
- 非人员分析单位 + PPS 必做；
- 未发布模板、未开放任务、已截止历史任务；
- 阶段 1/2/3/4、已提交、已评分、已驳回状态；
- PDF/DOCX 附件与 CSV/XLSX 总体。

### 5.2 独立统计基准

精确计算见统计清单 ST-B1–ST-B9。R2 至少执行：

| 夹具 | 用途 | 关键期望 |
| --- | --- | --- |
| D1 `N=1000,p=.5,E=.05` | 比例规划 | 最终邀请数 278 |
| D2 D1 + `deff=1.5,r=.2` | 调整顺序 | `n_fpc=365.810924...`，邀请 458，预期完成 366.4 |
| D3 `σ²=100,e=2` | 均值规划 | 最终邀请数 88；验证 `S²↔σ²` |
| D4 `[0,2,9,21,-1]`，`-1` 为缺失 | 描述统计 | 有效 4，均值 8，样本方差 90，R7 四分位数 1.5/5.5/12 |
| D5 `A:[0,2,4,6,8,10]`、`B:[10,20,30,40]` 非比例抽样 | 分层 | 估计 11.2，SE 3.296462750686964 |
| D6 `[0,100,0,0,100,0],n=2` | 系统设计 | 随机起点均值 0/100/0，SE 47.14045207910317 |
| D7 `y=[10,20,100],x=[1,2,3],n=1` | PPS 偏差反例 | 真均值 43.3333，Hájek 设计期望 58.3333，SE 41.79978734661484 |
| D8 值 `[2,10,40]`、权重 `[6,3,1]` | 非等权点估计 | 未加权 17.3333，加权 8.2 |
| D9 `['01','1',1,false,0,'01',null]` | 原始类型 | 单变量为 5 个有效编码；主分析差异必须被确认和解释 |

### 5.3 数值与结构反例

- 大数抵消：`[1e300, 1, -1e300]`；
- 相近大数：`[1e300, 1e300+1e284, 1e300-1e284]`；
- 次正规量级：`[1e-320, 2e-320, 3e-320]`；
- PPS 规模/权重跨 `1e-300` 到 `1e300`；
- N=1、N=2、n=1、n=N、n>N；
- 常量列、全缺失、非法文本、负数、零和极端尺度；
- 比例全 0、全 1、稀有目标未入样；
- 2/20/21 层、单单位层、层内普查、空层名、NFKC 冲突层名；
- 20/21/200/201 类，以及真实类别名“其他”“其余类别”“其余类别2”；
- CSV/XLSX 同一逻辑数据，含 `007`、CRLF、引号、逗号、换行、GB18030；
- 公式前缀 `= + - @`、NUL、超长多字节文件名、伪造 MIME/签名、损坏/高压缩 XLSX。

高精度预期可由十进制定点、任意精度库、R/Julia/Python 的独立脚本或人工枚举产生，但脚本及版本必须随证据保存，且不得导入项目代码。

## 8. R2：统计红队与独立复核

### 目标

主动寻找能让平台给出错误统计结论的输入，而不是证明典型示例能运行。

### A. 研究合同与解析

- 一行一个单位、重复记录、ID 重复、多选字符串和错误分析单位；
- 均值列完整性、有限性、方差、单位和 `σ²/S²`；
- 比例目标原始类型、空格、NFKC、大小写、零频类别和目标类别不存在；
- PPS 规模逐行正值、与目标不同、极端比例和必入单位；
- 分层字段完整、2–20 层、层名归一化与层容量；
- 问卷答案无论怎样变化，都不得改变总体、抽样框或估计。

### B. 规划与边界

- 执行 D1–D3，逐项比 raw 中间值、UI 取整、服务端保存和提交快照；
- 对置信水平、误差限、deff 和无回答率做两侧边界与单调性检查；
- 验证 `p` 与 `1-p` 对称，`p=.5` 最保守；
- 邀请数封顶 N 后重新判断可达精度；有无回答时不得把“邀请全体”标作普查；
- 高级 CV、成本、分层和整群规划只提供辅助结果，不能偷偷覆盖主计划。

### C. 四种抽样设计

- SRS：固定 seed 重放；小总体枚举/固定大批重复；每个样本唯一合法；
- 系统：分数间隔、随机起点边界、D6 精确枚举；打乱总体顺序后重新计算；
- 分层：D5、比例/等额/奈曼/成本分配、容量约束和整数余数；
- PPS：D7、`Σπ=n`、必入剥离、n=1、n=N、80%/120% 边界、不可表示概率；
- 对每种方法篡改 seed、index、row、π、weight、layer，后续分析必须拒绝；
- 相同 seed 重抽也必须形成新代次并使旧分析过期。

重复抽样的判定不能只看一次。建议用固定、留档的 seed 序列：先验收每次不变量，再比较单位纳入频率。频率阈值应在运行前按目标设计和重复次数确定并锁定；若使用模拟置信带，应做多重比较校正并避免把一次阈值外结果直接等同于算法错误。对系统和固定 π PPS，优先枚举全部随机起点分段，避免 Monte Carlo 漏掉稀有高影响区间。

### D. 估计、SE 与解释

- 执行 D4–D8，API 原值使用 `1e-12 + 1e-12×|期望|` 或预先推导的尺度容差；
- 四种设计不能共用 SRS SE；比例目标必须通过 0/1 目标使用同一设计；
- `MOE=z×SE`，改变 z 不改变点估计；
- `n_eff` 与实际 n 分开，SE=0 不自动等于普查；
- 稀有目标未入样时估计可为 0、设计 SE 可非 0；
- 对 PPS 明确展示 Hájek 可能有偏；对系统明确展示顺序敏感；
- 页面、API、数据库快照、师生详情一致；CSV 只按其现有契约核对样本、π 和权重，不虚构其未导出的统计列。

### E. 类型、缺失和图表

- 执行 D9，同时对主分析和单变量分析截屏并保存 raw API；
- 验证字符串/数字/布尔类型、缺失码和有效分母；
- 验证 20/21 类的图表聚合、完整统计空间、目标类别保留和“其他”标签冲突；
- 验证图表与 SVG 导出在负值、极小值、长标签和多方法下不截断/误导；
- 对“代表性偏差”增加零频类别，确认数值变化与文案不会被解释为统计检验。

### F. 数值稳定性与性质

对 5.3 的极端尺度运行主分析与单变量分析，结果必须与独立高精度参考一致或明确不可用，任何层都不得出现 JSON 非法数、假 0 或伪普查。

至少验证：

- 样本行与权重成对置换后结果不变；
- 所有权重乘相同正数后 Hájek 结果不变；
- `y'=a+by` 时均值线性变化，`b>0` 时 SD/SE/MOE 乘 b；
- 总体和样本同时置换且设计信息同步时，SRS/分层结果保持相应不变量；
- 分类频数之和等于有效数，比例之和在容差内为 1；
- 显示舍入不反写底层计算。

### R2 退出标准

- 统计清单所有 S0、S1 均有结果；
- 每种方法至少一个手算反例和一个边界/性质案例；
- O-STAT-01 至 O-STAT-05 已确认、修复或书面界定；
- 任一修复都有能让错误实现失败的非对称自动回归；
- 页面解释没有越过 `RESEARCH_MODEL.md` 的能力边界。

## 9. R3：并发、安全与故障注入

### 目标

证明系统面对过期客户端、重复请求、越权请求、部分故障和恶意文件时，不会泄露或形成半合法状态。

### A. 并发与幂等

- 两学生窗口保存不同问卷/规划、完成阶段、重抽、重开和提交；
- 提交 ↔ 重抽、提交 ↔ 重开、分析 Worker ↔ 上游重开/来源变化；
- 两教师窗口保存字典、发布模板、评分 ↔ 驳回、评分 ↔ 学生重提；
- 同/不同 `requestId` 在响应丢失后重试；19 条分析时并发新增两条；
- 当前学期并发切换，名册导入 ↔ 删除，模板复制 ↔ 总体替换。

每项都检查最终数据库，而不是只看两个 HTTP 响应。合法结果通常是“一个成功、一个明确冲突”或“幂等返回同一记录”，不能出现两个成功但状态互相覆盖。

### B. 鉴权与会话

- 未登录、错误角色、同班他人、跨班学生、另一教师直接请求读/写/下载；
- 修改所有对象 ID；确认 401/403/404 不泄露内部路径、SQL、堆栈或对象存在性；
- 同浏览器切换同角色账号后使用旧标签，验证 expected-user 冲突；
- 改密、管理员重置、删除账号后的旧密码和所有旧 Cookie；
- 退出网络失败与“旧退出响应晚于新登录”竞态；
- 错误 Content-Type、跨站 Origin/Referer/Sec-Fetch、重复身份参数。

### C. 文件与来源

- 0 字节、损坏/伪造类型、大小 ±1 B、行列上限 ±1、ZIP 解压预算；
- `../`、编码点号、绝对路径、反斜杠和超长中文名；
- 文件写入/删除失败、只读目录、磁盘空间不足，与发布/替换并发；
- 替换总体字节后读实验、提交、批改、分析和导出；
- 截断抽样 JSONB、删除总体文件、篡改压缩样本索引；
- 下载 Range、错误 Range、inline 预览、SVG sandbox 和外国附件。

### D. 服务故障

- 填满分析/总体统计队列，触发 30 秒期限和 Worker 崩溃；
- 分析排队时推进版本或跨过截止时间；
- 强制终止数据库连接，验证快速失败、连接池自愈和无半写；
- 请求落库后丢失响应，分别重试幂等和非幂等操作；
- SIGTERM 时有读取、上传或计算在途，验证优雅排空和重启一致性。

### R3 退出标准

- 无越权、跨用户数据、路径穿越、公式执行或 XSS；
- 无重复记录、半份快照、旧版本覆盖和数据库—文件悬挂引用；
- 所有超时/队满/来源冲突均有稳定可行动提示，恢复后可继续；
- 预期拒绝无数据库或文件副作用；
- 已知 500/409 错误面差异按风险清单记录，但任何不可恢复 5xx 都阻断。

## 10. R4：生产候选、容量与恢复

### 目标

证明真实生产构建和目标基础设施可承担课堂负载，并可从完整备份恢复。

### A. 生产构建与代理

- 用 `bun run start`，不用热更新或未构建的 production 入口；
- 检查三个 SPA、深链刷新、静态资源 gzip/cache、HTML no-cache；
- 确认普通生产包无 demo 凭据/端点，`DEV_AUTH_MODE` 已固定关闭；
- 检查 CSP、frame、nosniff、Referrer/Permissions Policy、CORP 和 API no-store；
- 在可信代理和直连下伪造 forwarded headers；只在 TLS 已强制时验证 HSTS；
- 验证代理超时长于 Worker 的 30 秒期限，应用错误可返回客户端。

### B. 容量阶梯

总体规模按 1k → 10k → 100k 行逐级执行上传、映射、规划、四种抽样、分析、导出。每级分别测冷/热缓存；上一档出现资源失控时停止放大并定位。

并发场景至少包含：

- 20 名学生读任务与保存阶段；
- 多人同时抽样/分析，教师同时看进度；
- 大文件导出时普通页面读取；
- Worker 队满后的恢复。

记录 p50/p95/max、吞吐、429/5xx、CPU、RSS、数据库连接和磁盘增长。通过阈值应在测试前由目标课堂规模和硬件 SLO 确定；不能测试后按结果改标准。最少要求合法上限内不 OOM、不长期阻塞普通读取，负载结束后 RSS/队列/连接回落且新请求成功。

### C. 配套备份恢复

1. 在停止写入的维护窗口同时备份 PostgreSQL 与 `storage/`；
2. 保存 SHA-256、应用 commit、迁移版本和时间戳；
3. 在 E3 校验 checksum，恢复到新空数据库和不存在的 storage 路径；
4. 运行迁移与 `storage:audit`；
5. 用恢复库启动生产构建；
6. 抽查三个角色登录、历史/当前任务、冻结提交、总体和附件下载、评分与导出；
7. 在另外的空迁移库执行 `test:db`，不要把固定集成夹具直接写入恢复库；
8. 证明只恢复数据库或只恢复文件时审计能发现问题，随后销毁该故障副本。

### D. 危险操作与清理

- `db:clean/reset/reset:demo` 在缺失/错误 `CONFIRM_DATABASE_NAME` 时必须拒绝；
- `storage:clean` 错误 token 必须拒绝，正确 token 也只能删 audit 列出的孤立文件；
- 检查所有临时数据库、浏览器 session、服务和文件已清理；
- 保留恢复副本到候选发布完成，不覆盖生产数据。

### R4 退出标准

- 生产主链与安全头通过，demo 能力未泄漏；
- 容量达到预定课堂规模且无资源泄漏；
- 数据库与 storage 配套恢复成功，关键历史证据可读；
- 危险命令保护有效；
- O-OPS-01/02 的人工监控和恢复证据齐全。

## 11. R5：修复回归与发布彩排

每个缺陷修复后执行三层回归：

1. 最小反例，证明原问题消失；
2. 同一所有权边界的相邻案例，防止局部修复改变别的方法/角色/状态；
3. 从登录到提交/批改的代表性主链。

候选 commit 冻结后重新运行 R0 的全部命令、R1 主闭环、所有 P0/S0、失败过的 P1/S1，以及 R4 生产启动与恢复抽查。任何代码变化都会使之前的构建、浏览器和恢复证据失效；纯文档修订可由负责人判断是否只重跑文档门禁。

## 13. 最终发布判定

只有同时满足以下条件才可签署：

1. P0/S0 失败为 0；
2. P1/S1 全部通过，或有具名风险接受人、原因、缓解措施、监控方式和到期日；
3. `verify`、`test:db`、`test:teaching` 在候选 commit 上全部通过，无伪装成通过的 skipped；
4. 完整 `bun audit` 已归档，接受公告及部署前提没有变化；
5. 每种抽样设计均有独立数值基准、边界和解释证据；
6. 提交快照、来源 SHA、抽样代次、分析引用和师生详情一致；
7. 生产构建、真实登录、代理/安全头、下载与导出已验收；
8. 达到预先声明的课堂容量；
9. PostgreSQL 与 `storage/` 的配套备份恢复已在独立环境完成；
10. 所有证据 manifest 绑定同一候选 commit，临时资源已清理。

若任一条件未满足，结论只能是“阻塞”或“带风险接受”，不能写“基本通过”。
