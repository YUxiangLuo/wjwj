# 默认商业统计案例与教学资料目录

默认演示库（`bun run db:reset:demo`）提供 5 个已发布并分配给主演示班 `2026级商务统计1班` 的标杆商业案例。全部案例均配备确定性合成商业总体、已确认的变量字典、商业研究合同（含支撑的管理决策）、差异化虚拟投放环境配置及推荐商业问卷。

## 五大商务统计实验总览

| 商业案例 | 核心目标指标 | 总体规模 | 正式轮策略重点 | 关键闭环教学问题 |
| --- | --- | ---: | --- | --- |
| 新锐现制茶饮新品定价与支付意愿调研 | 单杯最高支付意愿均值（元） | 240 名活跃会员 | 分层必做；PPS 禁用 | 普通会员高拒访导致试投幸存者偏差；会员等级分层抽样与定价补贴联动 |
| B2B企业SaaS重点客户年度增购预算调研 | 年度增购预算均值（万元） | 32 家重点客户 | 小总体 FPC；PPS 禁用 | 小总体有限总体校正、0 万元纯续约有效值量程边界、无合格正值规模列 |
| 综合电商平台付费会员年度续费率调研 | 到期“明确续费”比例 | 200 名付费会员 | 分层必做；PPS 禁用 | 沉默会员高拒访引发续费率虚高；活跃度分层抽样与事后权重校准对照 |
| 连锁生鲜超市晚高峰门店履约容量调研 | 15 分钟波次平均等待时长（分钟） | 96 个履约波次 | PPS 必做 | 非人员运营波次分析单位；ERP 台账「历史日均客单量」作为事前 PPS 规模变量 |
| 智能新能源汽车门店试驾潜客转化调研 | 30 天内“高意向锁单”比例 | 360 条试驾记录 | 系统抽样必做；PPS 禁用 | 门店能级隐式分层与 `n=90, K=4` 锁定单一到店时段引发的周期性共振风险 |

## 1. 新锐现制茶饮新品定价与支付意愿调研（旗舰从零体验入口）

- **商业决策背景**：确定「青禾茶事」下季度冷萃鲜果战略新品全国终端指导零售价区间，并制定普通/银卡/黑金三级会员的首发优惠券差额补贴策略。
- **总体与字段**：240 名活跃会员（普通会员 96 人、银卡会员 84 人、黑金会员 60 人），共 14 个业务字段，含会员等级、城市线级、常购门店商圈、消费场景偏好、最高支付意愿（元）、健康低糖关注度、新品尝鲜意愿、价格敏感度、月均茶饮消费额、近一月领券核销次数（0 次为原价购买有效值）及门店小程序体验评分（22 名近 3 个月未使用者为空白缺失）。配套三工作表 XLSX 工作簿（`总体数据`、`变量说明`、`调查说明`）。
- **虚拟投放特征**：黑金会员应答积极而普通会员拒访率较高，且混入少量闪电敷衍卷与直线作答卷。
- **零起点设计**：本课题在所有班级均**不预置任何学生实验记录**。任意演示学生账号登录后均可从 0% 完整体验五阶段多波次调研闭环。

## 2. B2B企业SaaS重点客户年度增购预算调研

- **商业决策背景**：核定大客户事业部下一财年 ARR 增购业绩目标与中型/大型集团客户交付顾问资源配比。
- **教学重点**：总体仅 32 家签约重点企业客户，有限总体校正（FPC）作用显著；纯续约不增购客户的预算为 `0` 万元（有效观测而非缺失，检验问卷 `numericMin: 0` 配置）；因无全正值辅助规模变量，PPS 按规范设为不适用。

## 3. 综合电商平台付费会员年度续费率调研

- **商业决策背景**：测算下年度会员订阅现金流基线，并针对低频沉默会员制定精准召回补贴券预算。
- **教学重点**：比例目标（误差限按百分点解释）；首轮简单随机试投会暴露低频沉默与濒临流失会员的高拒访幸存者偏差，驱动二轮按「近半年活跃度」开展分层抽样与无回答权重校准。

## 4. 连锁生鲜超市晚高峰门店履约容量调研

- **商业决策背景**：优化四家生鲜前置仓晚高峰 18:00 拥堵波次的兼职拣货员弹性排班。
- **教学重点**：分析单位为「一个 15 分钟前置仓晚高峰履约波次」而非单名顾客；利用总部台账事先已知且逐行严格为正的「历史日均客单量」执行必做 PPS 抽样，对比 Hájek 比估计相对等概率抽样的方差缩减效果。

## 5. 智能新能源汽车门店试驾潜客转化调研

- **商业决策背景**：评估旗舰店、商超店与城郊交付中心在不同到店时段的试驾锁单效率。
- **教学重点**：抽样框按三类门店能级成组，并在组内按「周末黄金档—工作日上午—工作日下午—晚间散客档」四时段固定循环；当规划 `n=90` 时系统抽样间距恰好为 `K=4`，不同随机起点会完全锁死在单一时段，直观展示系统抽样周期共振风险。

## 验证与重建

```sh
CONFIRM_DATABASE_NAME=<目标库名> bun run db:reset:demo
bun run db:seed:check
```

`db:seed:check` 会逐一核验 5 个商业课题的总体文件、确认态变量字典、研究合同、虚拟发放配置、推荐问卷、7 份已完成两轮闭环（`Wave 1 + Wave 2`）的提交/批改/驳回快照重放一致性及 `experiment_wave` 持久化记录。
