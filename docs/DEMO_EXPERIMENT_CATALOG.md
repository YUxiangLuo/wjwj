# 默认演示实验与教学资料

默认演示库提供 5 个完整、已发布且已分配给 `2026级统计学1班` 的实验。它们使用确定性生成的合成总体，不包含真实个人信息，也不用于给现实机构或人群下结论。

这套实验不是五个换标题的相同练习。每个实验都承担不同的统计教学任务，并明确区分研究问题、目标总体、分析单位、主指标和可用抽样设计。

## 实验总览

## 1. 青年幸福感调查（旗舰课题）

**研究问题**：示范地区调查时点所有 18—35 岁青年中，生活幸福感自评的平均水平是多少？

- 分析单位：一名 18—35 岁青年。
- 主指标：`生活幸福感得分`，0—10 分，允许 1 位小数。
- 分层字段：年龄组、居住地类型、当前状态；教学任务要求至少完成年龄组分层。
- 情境为虚构的青禾示范地区青年服务需求调查，纳入连续居住满6个月的18—35岁常住青年，覆盖9个社区。
- 三个年龄层分别为96、84、60人，供学生练习不同层大小下的样本分配。合成总体设置了可观察的层间差异，同时保留组内重叠；这只是教学信号，不表示现实年龄效应。
- 总体共14个字段，包含年龄、居住社区、居住方式、学习就业状态、社会支持、自评健康、经济压力、每晚睡眠、每周休闲和社区服务满意度。
- 每周休闲时长的0值为有效观测；社区服务满意度空白表示近3个月未使用过服务，应从满意度有效分母中排除。变量字典已确认，可直接开展单变量分析。
- 服务满意度放在“其他字段”组，字典仍按五级有序分类解释。采用对应推荐题后，在“关联变量”中选同名字段，再明确选择“近3个月未使用过”为缺失选项；它对应空白，不作为第六级满意度计入比例。
- 方法边界：青年个体没有自然且事先已知的“规模”变量。即使软件能识别正数列，也不能把幸福感、自评健康或社会支持感当作 PPS 规模变量。
- 解释边界：主指标是总体生活评价的单题测量，不是经过临床验证的诊断量表；横截面分组差异不支持因果解释。

推荐问卷有14题，按筛选题、主体题和背景题组织，明确年龄与居住条件、评分端点和回忆时间，并为未使用社区服务者提供单独选项。总体工作簿包含“总体数据”“变量说明”“调查说明”三个工作表。

**从零体验入口**：本课题不预置任何学生实验、提交或成绩，包括历史班任务。主演示班10名学生均为“未开始”；随机登录任何演示学生都可从问卷设计开始。学生开始后正常保存进度，不会在登录时自动重置。

## 2. 学生每周阅读时长

**研究问题**：该校学生每周课外阅读时长的平均水平是多少？

- 分析单位：一名学生。
- 总体只有 24 个单位，并保留真实可出现的零阅读时长。
- 推荐问卷使用带“小时”单位的数值题直接测量主指标，明确将无课外阅读记录为 0，而不是用模糊区间替代均值变量。
- 数据中没有对每个单位都严格为正、且适合作为事先规模度量的字段，因此禁用 PPS。
- 教学重点：比较样本调查与普查，观察有限总体校正；讨论零值是有效观测还是缺失值。
- 报告要求：不能为了“做满四种方法”而虚构规模变量，也不能删除零值来美化分布。

## 3. 毕业生直接就业意向比例

**研究问题**：某综合大学 2026 届全体毕业生中，计划直接就业的学生比例是多少？

- 分析单位：一名毕业生。
- 主指标：`毕业去向意向` 是否为“直接就业”。
- 学院分层必做，培养层次可作为第二个分组视角。
- 样本量采用比例估计的保守方差，误差限必须以“百分点”表述。
- 求职准备度和每周职业准备时长是分析辅助变量，不是表示个人规模的抽样框变量，因此禁用 PPS。
- 报告不得把意向等同于最终去向，也不得外推到其他学校或毕业年份。

## 4. 食堂午间等待时间

**研究问题**：两个教学周内选定的六个观测日中，两校区四个食堂的 96 个午间 15 分钟服务时段，平均等待时间是多少？

- 分析单位：一个 15 分钟服务时段，不是一名学生，也不是一家食堂。
- 推荐工具是由观察员填写的“服务时段观测表”，地点、观测日和时段共同标识一个总体单位；它不是面向单个就餐者的满意度问卷。
- 测量规程：每个抽中时段从开始后最先加入队列的 5 名就餐者开始观察（不足 5 名则观察全部），从站到队尾起计时，到窗口开始受理点餐或结算时停止，再计算算术平均；若无人入队，按本实验预先约定将该时段等待负担记为 0 分钟，并记录有效观察人数为 0。
- 主指标：现场记录的等待分钟；规模变量：抽样框中事先已知的历史同期客流量。实际开放窗口数也在抽中时段现场记录，但不参与事前纳入概率计算。
- PPS 必做，用于展示不等概率抽样、纳入概率和设计权重；同时可按校区分层。
- 报告需区分“按服务时段等权的平均等待负担”和“按就餐人数加权的个人平均等待”。前者是本实验目标，后者需要不同的估计量和观察方案。
- 合成数据交叉覆盖四个食堂和四个时段，并设置历史同期客流量增加、窗口数增加分别影响等待时间的教学信号；这些关系只能作设计演示，不能推出真实食堂的因果效果。

## 5. 校园绿色通勤方式占比

**研究问题**：正常教学周学生典型到校通勤记录中，步行、自行车或公共交通所占比例是多少？

- 分析单位：一名学生的一次典型到校通勤记录。
- 主指标：`是否绿色通勤` 为“是”的比例。
- 抽样框先按住宿片区成组，每组内再按四个登记时段固定轮换。按 95% 置信水平、±9 个百分点规划会得到 `n=90`、`K=4`：不同随机起点会固定抽中不同登记时段，从而直接展示周期性风险；同时，跨越三个片区又展示有序抽样框可能形成的隐式分层。应与简单随机结果比较，且不能用一次“更接近真值”的结果判断设计优劣。
- 通勤距离虽是严格正数，但不代表个人或通勤记录的“规模”，所以禁用 PPS。
- 报告需使用比例和百分点，不得把样本中的绿色通勤条数直接解释为总体人数。

## 建议演示顺序

1. 用“青年幸福感”讲清研究合同、问卷主指标、分层与解释边界。
2. 用“阅读时长”展示小总体、有限总体校正和 PPS 不适用。
3. 用“毕业去向”从均值切换到比例，并强调百分点。
4. 用“食堂等待”讲分析单位、PPS、纳入概率和权重。
5. 用“绿色通勤”收束到抽样框排序和系统抽样风险。

每个实验均包含：合成总体表、字段映射、研究合同、推荐问卷、抽样策略和评分权重。青年幸福感课题另附数据上传规范及调查问卷设计模板。阅读、毕业去向、食堂等待和绿色通勤保留提交与批改样例；青年幸福感专供从零开始体验。

## 验证与重建

```sh
bun run db:reset:demo
bun run db:seed:check
```

`db:seed:check` 会验证 5 个课题均已发布并分配给主演示班、总体文件可解析、字段与目标一致、问卷有效、抽样策略正确、样本计划可由总体重新计算，以及冻结提交与抽样审计记录完整。

已有演示库可以使用 `bun scripts/refresh-happiness-demo.ts` 预览定向更新范围。完成数据库与 storage 配套备份并停止应用写入后，设置 `DEMO_MODE=1`、`CONFIRM_DATABASE_NAME=<目标库名>`，再加 `--apply` 执行。脚本只匹配 T001 名下使用已知 seed 总体文件的青年幸福感课题，替换其内容并清除该课题所有任务的学生实验；相关班级的旧学生会话会失效，重新登录后开始。其他课题的实验、账号和任务不重建。

已经使用 v2 幸福感总体的演示库，如只需修正服务满意度的字段角色，使用 `bun scripts/repair-happiness-mapping.ts` 预览。备份并停止应用写入后，以相同的 `DEMO_MODE=1` 和数据库名确认加 `--apply` 执行。它只更新字段映射与字典来源/修订号，保留问卷、总体文件、账号和会话；如尚未修复且已有学生实验则拒绝执行。修复后的重复执行不再增加修订号，也不重置任何进度。
