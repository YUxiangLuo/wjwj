# 高风险测试检查清单

本文供测试人员在发布前逐项检查，目标是优先发现最可能造成**统计结论错误、越权、数据污染、材料丢失或无法恢复**的问题。它不是逐页 UI 清单，也不替代自动化测试。

清单基于当前实现、[教学规则](TEACHING.md)、[课题模型](../RESEARCH_MODEL.md)、[安全边界](../SECURITY.md)、[运行与部署](OPERATIONS.md)、[数据库操作](../DATABASE.md)，以及仓库中的单元、真实数据库和教学闭环测试整理。三轮 Dogfood 暴露的实际缺陷已固化为第 5 节的“历史缺陷热点”，不依赖未入库的测试报告。外部方法参考见文末。

统计公式、独立数值基准和专业解释要求见[统计学专业验收清单](STATISTICAL_TEST_CHECKLIST.md)。

## 1. 怎么使用

### 优先级与判定

| 级别 | 含义 | 发布要求 |
| --- | --- | --- |
| P0 | 错误统计结果、越权、跨用户数据、错误来源、重复/半份写入、提交快照污染 | 必须全部通过 |
| P1 | 主流程中断、冲突后丢数据、不可恢复删除、容量或生产配置失效 | 必须通过，或由负责人书面接受风险 |
| P2 | 可访问性、兼容性、提示和非关键展示问题 | 记录并排期 |

每项记录：代码版本、环境、账号/数据夹具、操作步骤、预期与实际、响应状态和错误码、数据库断言、截图或日志位置。不能只记“点过了”或“没有报错”。预期的 401/403/404/409/429/503 是正确结果时，不应当作服务异常。

### 安全准备

- [ ] 使用独立、已迁移、可丢弃的测试库和独立 `storage/`，不得对应用库执行 reset。
- [ ] 只上传合成或充分脱敏数据；总体行可被学生重抽并完整导出。
- [ ] 真实账号验收使用 `DEV_AUTH_MODE=0`；生产验收使用 `bun run start`，不能只测热更新开发服务器。
- [ ] 至少准备管理员 1 名、教师 2 名、不同班学生各 2 名，用于跨角色、跨教师、跨班和同班他人的权限检查。
- [ ] 准备一个完整四阶段课题、一个不含变量字典/关联/分析引用的最简课题，以及下文边界数据。
- [ ] 涉及并发时使用两个独立窗口或连接，并核对最终数据库状态；不能仅根据两个 HTTP 响应推断没有竞争写入。

建议先运行基线：

```sh
bun run verify
bun run test:db
bun run test:teaching
```

缺少 `TEST_DATABASE_URL` 或创建临时库权限时应记为“阻塞”，不能把 skipped 记为通过。

## 2. P0：必须优先检查

### A. 实验状态机、重开与提交冻结

这一区域跨问卷、规划、抽样、分析和提交，最容易出现“界面看似成功，但保存的是新旧材料混合物”。

| ID | 操作 | 通过标准 |
| --- | --- | --- |
| RK-A01 | 依次尝试跳过阶段、重复完成阶段、缺少一个必做抽样方法、只完成一种方法 | 服务端拒绝，阶段、版本和已有成果均不变；提示指出缺少的条件 |
| RK-A02 | 分别重开阶段 4、3、2、1，并在每次操作后检查报告、引用、分析记录、抽样结果和代次 | 清理范围符合[教学规则](TEACHING.md)；阶段 1–3 重开使旧分析永久过期，抽样代次单调增加；阶段 4 重开不误删上游结果 |
| RK-A03 | 保存分析引用后重抽同一方法，即使使用相同种子 | 只替换该方法的当前结果；其他方法保留；旧引用明确过期，不因相同索引而复活 |
| RK-A04 | 正常完成阶段 4 后提交；随后尝试完成/重开/重抽/改报告 | 提交前只允许完整合法材料；提交后实验锁定，不发生额外写入 |
| RK-A05 | 提交后在隔离库中修改当前变量字典或删除分析记录，再分别从学生端和教师端读取详情 | 两端仍显示同一份冻结字典、关联、引用、结果和证据，不回填当前可变数据 |
| RK-A06 | 提交后替换总体文件字节，再读取冻结样本 | 哈希不一致时明确返回 `SOURCE_CONFLICT`，绝不能用新总体中的同一行号恢复旧样本 |
| RK-A07 | 报告正文测试 99/100/5000/5001 字、纯空白富文本、脚本内容；引用测试 0/10/11 条 | 正文边界正确；附录不计入正文；清洗后内容安全；最多 10 条且无引用仍可提交；失败不部分保存 |
| RK-A08 | 提交后教师驳回，学生修改并重提，再评分 | 驳回原因可见；实验重新可编辑；旧分数和评语不残留；重提形成一致的新冻结材料 |

### B. 多窗口、并发与幂等

| ID | 操作 | 通过标准 |
| --- | --- | --- |
| RK-B01 | 两个学生窗口基于同一版本分别保存不同问卷或规划 | 仅一个成功；另一个明确提示版本冲突并保留本地输入，不自动合并或覆盖服务器版本 |
| RK-B02 | 同时完成同一阶段、同时提交、提交与重抽、提交与重开 | 最终只能存在一个合法状态；提交重试可以幂等成功，但数据库只有一份提交快照和一次版本推进 |
| RK-B03 | 两个教师窗口基于同一 revision 保存不同字典 | 仅一个成功，败者不覆盖；revision 只增加一次 |
| RK-B04 | 并发执行“字典保存 ↔ 发布”“映射保存 ↔ 发布”“总体替换 ↔ 复制模板” | 最终要么完整采用新配置，要么拒绝修改；不能出现冻结后补写或副本混合两个时点的数据 |
| RK-B05 | 并发评分与驳回、学生重提与教师评分 | 最终状态唯一，分数、评语、驳回原因与状态匹配，不产生半份审计记录 |
| RK-B06 | 19 条已存分析下同时创建两条新分析；同一 `requestId` 在响应丢失后重试 | 容量最终为 20；只有一条竞争请求新增成功；同请求返回原记录，不重复计算或写入 |
| RK-B07 | 并发切换“当前学期”；同时执行名册导入与学生删除 | 始终恰好一个当前学期；学生不重复、不处于半导入状态，无死锁 |

### C. 统计计算与数据边界

期望值必须手算或由独立工具生成，不能调用被测函数生成自己的期望。比例/均值样本量、描述统计、分层与加权点估计的**精确数值基准统一维护在[统计学专业验收清单](STATISTICAL_TEST_CHECKLIST.md)的 ST-B1–ST-B9**；本节只保留高风险清单独有的操作与通过条件，不重复维护同一批数字。

| ID | 数据/操作 | 通过标准 |
| --- | --- | --- |
| RK-C01 | N=1、N=2；抽样量 n=1、n=N、n>N | 合法边界正确；普查 SE=0；越界拒绝；页面和导出无 NaN/Infinity |
| RK-C02 | 均值列含负数、小数、零、极大/极小尺度、常量、缺失、非数值 | 支持的值与独立计算一致；常量、全缺失或无法可靠算方差时在映射/规划处显式拒绝，不以 0 或默认方差代替；注意数值列的缺失须用字典声明的缺失码表示，空单元格会被映射校验拒绝 |
| RK-C03 | 比例总体全属于目标、样本未抽到稀有目标、字典中存在零频类别 | 估计可为 0 或 1；设计 SE 按总体信息计算；零频类别仍显示；非普查不能误标为普查 |
| RK-C04 | 系统抽样使用 N=10/100、n=3/7，检查分数间隔和接近边界的随机起点 | 样本数精确、索引唯一、可按种子复现，不因整数取整丢行或重复 |
| RK-C05 | PPS 规模值含 0、负数、缺失、全零；规模列等于目标列；含 π=1 必入单元 | 非法规模列/同列配置拒绝；必入单元权重为 1；80%/120% 样本量边界通过，79%/121% 拒绝 |
| RK-C06 | 分层 2/20/21 层、单单位层、层内普查、空分层值；比例/等额/奈曼分配 | 只接受 2–20 个有效层；分配数与手算一致且总数不丢；非法层配置不落库 |
| RK-C07 | 规划置信度 89/90/95/99/100，设计效应 0.49/0.5/5/5.1，无回答率 0/0.5/0.51 | 仅文档规定的值和边界通过；拒绝发生在**阶段完成与提交校验**（`submit-validation`：设计效应 0.5–5、无回答率 0–50%），内部归一化函数对历史数据的回退不据此判失败；邀请数按回答率调整并以总体 N 封顶 |
| RK-C08 | 均值规划时伪造客户端总体方差，或在计算后带外替换总体 | 阶段完成与最终提交都按当前总体复核方差口径；伪造/过期计划拒绝，不静默沿用 |
| RK-C09 | 非对称数据与缺失（夹具与期望值见统计清单 ST-B4） | 与独立基准一致；0 不被当作缺失；SD 不显示为 SE |
| RK-C10 | 非等权点估计（夹具与期望值见统计清单 ST-B9） | 与独立基准一致；权重频数不冒充人数，不提供未实现的加权 SD/分位数/区间 |

### D. 鉴权、会话与对象级权限

不要只隐藏菜单。每项都应直接调用真实 API，并确认无数据库副作用。

| ID | 操作 | 通过标准 |
| --- | --- | --- |
| RK-D01 | 未登录及错误角色访问三个入口的读取、写入、下载接口 | 返回稳定的 401/403/404；响应不泄露对象是否存在、内部路径、SQL 或堆栈 |
| RK-D02 | 修改 task/topic/class/student/experiment/attachment ID，覆盖同班他人、跨班学生和另一教师资源 | 不可读取、修改、评分、导出或下载；失败后目标资源完全不变 |
| RK-D03 | 同一浏览器依次登录两个同角色账号，保留旧标签页继续读写/下载 | 旧页检测身份变化并停止写入；`expected_user_id` 不一致返回冲突，不发生串号 |
| RK-D04 | 登录后改密，再使用旧 Cookie 和旧密码；管理员/教师重置密码后重复检查 | 当前会话按规则旋转；其他旧会话失效；旧密码失效；会话撤销与密码变更原子完成 |
| RK-D05 | 发起退出时模拟网络失败，再正常退出；同时在另一标签重新登录 | 失败时明确提示“尚未安全退出”；成功后旧会话失效；旧退出响应不能清除更新后的登录会话 |
| RK-D06 | 对写接口发送错误/缺失 Content-Type、跨站 Origin/Referer/Sec-Fetch，以及重复 `expected_user_id` | 分别稳定拒绝，无任何写副作用；不能通过重复参数选择一个合法身份绕过 |

### E. 文件、来源完整性与导出

| ID | 操作 | 通过标准 |
| --- | --- | --- |
| RK-E01 | 总体 CSV/XLSX：0 字节、损坏 XLSX、`.xls` 改后缀、空/重复/保留前缀列名、50/51 列、100000/100001 行 | 仅合法边界通过；不截断、不重排行；失败不留下数据库记录或孤立文件 |
| RK-E02 | CSV 分别使用 UTF-8 BOM、无 BOM UTF-8、GBK/GB18030、CRLF、引号/逗号/换行，编号 `007` | 编码预览可识别且需人工确认；乱码不能靠切换编码“修复”；编号和单元格边界保持 |
| RK-E03 | XLSX 包含高压缩比内容、过多 ZIP 条目或超预算解压体积 | 在解析前/解析中受限并明确拒绝，不导致进程 OOM 或长时间阻塞 |
| RK-E04 | 附件伪造扩展名/MIME/文件签名，上传 SVG、双扩展、路径字符、超长中文文件名；测试大小边界 ±1 B | 扩展名和基础签名共同校验；限制按实际类型生效；多字节名称不造成 500；保存路径不能穿越存储目录 |
| RK-E05 | 删除/替换总体或附件时注入文件系统只读、写失败、删除失败，并与发布并发 | 数据库与文件引用保持一致；失败可恢复；不能出现已发布模板引用不存在文件或误删仍被引用文件 |
| RK-E06 | 学生样本 CSV 和教师成绩 XLSX 中加入以 `=`, `+`, `-`, `@` 开头的字段，以及引号、换行、前导零 | 表格软件打开时不执行公式；数据内容、列数、行数、BOM 和前导零符合导出契约 |
| RK-E07 | 请求 `/templates/:name` 和下载接口，使用 `../`、编码点号、绝对路径、反斜杠 | 统一拒绝，不能读取模板/存储目录之外文件 |
| RK-E08 | 人为截断已完成的抽样 JSONB，或删除总体文件后执行分析/导出/批改 | 返回 `INVALID_SAMPLING_STORAGE` 或明确来源错误；不能把损坏记录当作空结果，也不能产生新分析或成绩 |

## 3. P1：主流程与可恢复性

### F. 草稿、截止时间和失败恢复

| ID | 操作 | 通过标准 |
| --- | --- | --- |
| RK-F01 | 问卷、规划、报告分别输入未保存内容后刷新；测试 7 天过期、版本变化、localStorage 禁用 | 合法草稿按实验恢复；过期/错版本草稿不覆盖服务器；存储不可用时仍能操作并明确提示没有本地保障 |
| RK-F02 | 两个标签先后编辑同一草稿 | 后来的服务器版本变化会阻止旧页继续覆盖；不自动合并；用户可复制未保存内容后再重载 |
| RK-F03 | 任务开放前、截止前后各 1 秒执行进入、完成阶段、抽样、分析、提交 | 开放前/已截止正确拒绝；时间按 UTC+8 展示且服务端为准；截止前已受理的任务可跨截止完成，这是当前约定 |
| RK-F04 | 分析 Worker 排队中重开上游、变更来源、提交或跨截止 | 最终写入前复核版本、状态、来源和抽样代次；失效计算不入库 |
| RK-F05 | 填满 Worker 队列、触发 30 秒超时和 Worker 崩溃，再释放负载 | 返回 429/503、稳定错误码和合理 `Retry-After`；页面不无限转圈；恢复后新请求成功，无半写和资源泄漏 |
| RK-F06 | 请求已经落库但响应丢失、请求在途断网、数据库连接被终止后重试 | 幂等操作不重复；非幂等操作明确告知用户刷新核对；连接恢复后服务可继续使用 |

| RK-G04 | 删除学生、任务、模板、班级、教师、学期；分别制造未提交、已提交、已评分引用 | 阻塞和级联计数与实际一致；高影响删除必须二次明确确认；删除后会话撤销，无孤立数据库行或文件 |

| RK-G06 | 公告 all/teacher/student、未上架/下架、富文本脚本、超长内容 | 三端可见范围正确；脚本在任何渲染入口均不执行；状态变更及时、排序稳定 |

| RK-H06 | 同时备份 PostgreSQL 与 `storage/`，恢复到独立空库后启动应用 | 校验和正确；迁移、`test:db`、`storage:audit` 通过；典型总体和附件可下载；不能只恢复其中一部分 |
| RK-H07 | 对 `db:clean`/`db:reset` 使用缺失或错误 `CONFIRM_DATABASE_NAME`；对 `storage:clean` 使用错误 token | 全部拒绝且原数据不变；正确 token 也只能清理由 audit 列出的孤立文件 |

## 4. P2：浏览器与可访问性

- [ ] 仅用键盘完成登录、模板向导、变量字典、问题关联、四阶段、提交确认和评分确认；焦点可见，打开/关闭对话框后焦点位置合理。
- [ ] 校验错误不仅靠颜色表达，错误文字指出字段与修复方式；提交、保存、队列等待等状态变化可被辅助技术感知。
- [ ] 模态框打开后背景不可交互；隐藏页签中的控件不进入 Tab 顺序；Escape、取消和危险确认行为一致。
- [ ] 1024px 桌面宽度、200% 缩放、长中文/英文/emoji/RTL 文本、10 条分析附录、大表格下，关键按钮和正文不被遮挡；允许横向滚动的表格仍有可达操作。
- [ ] 浏览器后退/前进、深链刷新、快速重复点击、慢网和 API 失败时不出现空白页；错误边界提供有效恢复入口。
- [ ] 日期始终明确按中国标准时间（UTC+8）展示；截止倒计时、绝对时间和服务端判定不矛盾。

## 5. 历史缺陷热点：每次发布都回归

这些问题在真实 Dogfood 中出现过，说明其相邻路径容易再次出错：

- [ ] 均值规划使用的总体方差：客户端伪造、总体替换，以及 σ²（分母 N）与 S²（分母 N−1）口径。
- [ ] 中文等多字节上传文件名接近文件系统 255 字节限制时不得返回 500，扩展名仍需保留。
- [ ] JSON 文本字段中的原始 NUL 和 `\u0000` 应统一返回 400，不能进入 PostgreSQL 后变成 500。
- [ ] 已完成但缺少样本行的损坏抽样存储必须 fail closed，不能被解释为空的旧格式。
- [ ] 数值题不能通过 `Number()` 把 null、布尔、数组或对象静默强转为 0/1；合法数值输入按 Enter 应能继续。
- [ ] PPS 纳入概率必须满足 `0 < π ≤ 1`；π>1 不能产生看似正常的小于 1 的设计权重。
- [ ] CSV 空单元不能被错误建议为空字符串类别，继而让系统自己的字典校验无法通过。

## 6. 当前产品边界：避免误判，也要防止范围外泄

以下是当前明确边界，不应直接报成回归缺陷；若实际行为超出边界或提示与之矛盾，仍应报告：

- 系统定位为受信任内网、桌面端、浅色主题、单实例本地文件存储；多实例必须先改用共享存储。
- 问卷答案只用于认知预试，不进入总体估计；总体分析只支持一个数值均值或明确类别比例的主要目标。
- 问卷、规划和报告草稿仅在当前浏览器保存 7 天，不跨设备同步；退出登录会保留并按实验 ID 隔离草稿。
- 截止前已被服务端受理的工作允许在排队或持锁期间跨过截止后落库。
- 当前没有首次登录强制改密、登录失败锁定或登录限速；这属于已知安全缺口，公开部署前应重新评估。
- 当前审计主要覆盖删除、批改和驳回，不覆盖登录、改密、模板发布；需要合规审计时不能假设已经具备。
- 公告历史记录显示“存储原文、渲染时清洗”；测试必须覆盖每一个渲染入口，任何绕过统一渲染组件的页面都可能重新引入 XSS。
- 1024px 下报告辅助卡片可能需要横向滚动；正文和提交主路径被遮挡才是阻断问题。

## 7. 推荐执行顺序与退出标准

1. **20–30 分钟冒烟**：RK-A01、RK-A04、RK-D01、RK-D02、RK-E01、RK-H01、RK-H03。
2. **核心发布回归**：A/B/C/D/E 全部，重点保留数据库断言和冻结前后证据。
3. **恢复与运维验收**：F/G/H；数据库或文件变更后必须执行 RK-H06。
4. **真实浏览器验收**：完成 P2，并检查控制台错误、失败请求和代表性截图。
5. **自动化门禁收尾**：重新运行 `verify`、`test:db`、`test:teaching`。

退出标准：P0 为 0 个失败；P1 全部通过或有明确的风险接受人和期限；所有新缺陷有最小复现数据，修复后加入能区分正确/错误实现的自动化回归；测试创建的服务器、临时库和文件已清理。
