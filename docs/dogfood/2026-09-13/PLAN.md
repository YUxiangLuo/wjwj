# 独立全量验收轮次（DG 系列）

计划日期：2026-09-10 CST。计划窗口：2026-09-13 起，约 8–11 人日。

> **独立性声明。** 本轮**不引用、不继承**任何既有 dogfood 记录（包括既有批次计划、执行报告、缺陷台账与修复报告）。覆盖范围全部从**产品自身**推导：源码、路由表、数据库 schema、设计系统与运行配置。因此本轮的用例编号使用独立的 `DG-` 前缀，判定基准是产品契约本身，而不是“上一轮漏了什么”。
>
> 既有记录唯一被允许的用途是**事后交叉核对**（例如确认某个历史缺陷是否在本轮仍能复现），交叉核对结果不得替代本轮独立证据。

## 一、被测对象的事实基线

从源码盘点得到的事实（本轮覆盖面的依据）：

| 维度 | 事实 |
| --- | --- |
| 运行时 | 单进程 `Bun.serve`，三个独立 SPA（`/student`、`/teacher`、`/admin`，根路径 302） |
| 接口面 | **85 个** `/api/**` 端点（学生 17、教师 34、管理 26，另含登出/密码等） |
| 数据模型 | **13 张表**：admin、teacher、student、semester、class、topic、topic_attachment、task、experiment、sampling_attempt、announcement、audit_event、user_session |
| 学生四阶段 | 问卷预试 → 样本量规划 → 抽样执行 → 分析与报告 |
| 题型 | `boolean` / `single` / `multiple` / `scale`（1–10），问卷标题 1–100 字、欢迎语与结束语各 20–1000 字、题目 5–50 道 |
| 抽样方法 | 简单随机（**固定必做**）、系统抽样（允许分数间隔）、PPS（πps，Hájek 加权）、分层（比例/等额/奈曼） |
| 抽样策略 | 至少启用 2 种；必做方法必须全部完成；PPS 样本量须落在目标量的 **80%–120%**（并被总体量封顶） |
| 高级规划 | `cost` / `multivar` / `cv` / `cluster` 四类，带可复核快照 |
| 分析工作区 | 研究结果 / 图表探索 / 规划与抽样记录 / 撰写报告 |
| 学生导出 | `simple` / `systematic` / `pps` / `stratified` / `all`，PPS 附带包含概率与设计权重列 |
| 教师成绩导出 | `preview` / `analytics`（漏斗、均值、中位数、三项均分）/ `data` / `excel` |
| 文件边界 | 总体表仅 `.csv`/`.xlsx` 且 ≤20 MiB、≤100,000 行、≤50 列；JSON 请求体 ≤256 KiB；附件单模板 ≤20 个、合计 ≤500 MiB，图片 10 / 文档 50 / 视频 120 MiB |
| 背景服务 | 分析 Worker（队列上限默认 64、含排队 30 秒上限）、总体统计 Worker、密码服务队列（并发 2–4 默认 4、队列 4–128 默认 64） |
| 会话 | 按角色独立 Cookie；写请求 `X-Expected-User-Id`；原生资源 `expected_user_id`；不匹配即拒绝 |
| 公告 | `target_scope` ∈ {all, teacher, student}，仅 `status=1` 对对应角色可见；**不按班级/学期细分** |
| 学期 | 单一“当前学期”由部分唯一索引保证 |
| 保留策略 | 浏览器草稿 7 天；服务端抽样记录每实验最近 100 条 |
| 任务时间 | `open_time` / `deadline`；接纳后允许在截止后完成，但截止后不接受新写入 |
| 配置面 | 21 个环境变量（数据库、端口、鉴权模式、并发上限、队列上限、代理信任、seed 锚点等） |
| 模板资源 | `/templates/:name` 提供 `数据上传规范.pdf`、`数据模板.csv`、`调查问卷设计规范与模板.docx|.pdf` |

## 二、风险模型

按“对真实课堂的危害程度”排序，作为用例优先级依据：

| 等级 | 风险 | 典型后果 |
| --- | --- | --- |
| R1 | 统计结果实质错误（估计量、设计标准误、区间、分配） | 教学传授错误方法，学生形成错误直觉 |
| R2 | 越权或身份串写（跨班、跨教师、跨角色、账号切换） | 成绩与样本泄漏、写错账号 |
| R3 | 数据丢失或不可恢复（草稿、提交快照、级联删除） | 学生劳动成果消失、成绩无法追溯 |
| R4 | 状态机被绕过（阶段顺序、截止时间、重复提交、重复评分） | 成绩不可信 |
| R5 | 容量与可用性（课堂同步登录、分析排队、Worker 超时） | 上课时段不可用 |
| R6 | 文件与注入（上传伪装、路径穿越、富文本/公式注入） | 服务器或导出文件被利用 |
| R7 | 教学语义错误（术语、单位、百分点 vs 比例、误差半宽被误读） | 概念性误导 |
| R8 | 体验与无障碍阻断（键盘不可用、遮挡、对比度） | 部分学生无法完成 |
| R9 | 运维与可恢复性（部署、迁移、备份恢复、依赖公告） | 无法交付或无法恢复 |

## 四、环境与数据（从零重建）

**不使用任何既有夹具、既有 dogfood 数据库或既有部署目录。** 全部重建，以便同时验证“首次部署”路径。

```sh
DSTAMP=$(date +%Y%m%d-%H%M)
SNAP=/root/pros/wenjuan/dg-runs/dg-$DSTAMP
git -C /root/pros/wjwj archive --format=tar HEAD | tar -x -C "$SNAP"   # 只取已提交版本
cd "$SNAP" && bun install --frozen-lockfile
```

| 资源 | 约定 |
| --- | --- |
| 快照 | 每个**被测 commit** 一个目录；不修改其源码（除本轮的测试脚本目录） |
| 数据库 | 每轮 `dg_<dstamp>`（空库，跑 `db:migrate` → `db:bootstrap-admin`），另备 `dg_<dstamp>_r` 供破坏性用例 |
| 端口 | 从 **6500** 起顺序分配，一轮一实例；不占用 3000/6363/3100/6468/6470 |
| 存储 | 随快照目录（`process.cwd()/storage`）；破坏性用例使用独立快照目录 |
| 模式 | `NODE_ENV=production`、`DEMO_MODE=0`、`DEV_AUTH_MODE=0` |
| 账号 | **全部经管理端页面创建**：1 管理员（`db:bootstrap-admin` 生成口令）→ N 教师 → N 班级 → 50 学生（页面导入） |
| 数据 | 合成数据；主要总体用一个独立生成器产出，含均值/比例/含负值/常数列/含必入规模等场景 |
| 时钟 | 不修改主机时钟；时间相关用例使用**短窗口任务**或独立实例 |

**必做**：`DG-O-01` 必须在完全空库上从 `db:migrate` + `db:bootstrap-admin` 走通首次部署，确认空状态下三端无虚假数据、无默认学期、无预置账号。

### DG-N 统计与数值（16）

> 独立 oracle 要求：本域所有期望值必须来自**不导入生产计算模块**的独立实现（精确有理数/穷举/闭式解），不得用生产函数自对账。

| --- | --- | --- |

| DG-N-05 | P0 | PPS 包含概率：独立解 `π=min(1,λ·规模)`，核对 Σπ=n、必入集合、边际入样概率 |

## 六、执行纪律与证据

- 浏览器一律用 `agent-browser`，每角色独立 session；跨标签测试用同 session 多 tab，跨浏览器用不同 session，两者不混用。
- **写操作优先走真实页面控件**；需要大量夹具时允许用已授权真实 API 准备，但必须在用例中标注“API 辅助”，不得据此声称纯 UI 通过。
- 数据库只读核对；**禁止用写 SQL 把失败流程“修通”**。
- 数值判定默认容差 `max(1e-10, 1e-8·|期望|)`；整数与行集合精确比较；极端量级先声明误差界，不为通过而放宽。
- 故障注入优先用**独立故障代理**（支持返回状态码、延迟、以及“先转发再失败”），而不是改产品代码。
- 每用例记录：ID、被测 commit、角色、URL、前置数据、步骤、预期、实际、状态（PASS/FAIL/BLOCKED/NOT_RUN）、证据路径、控制台/HTTP 错误、只读数据断言、复现频率。
- 证据不得包含 Cookie、会话令牌或口令明文；截图避开口令字段与真实个人信息。
- 目录结构：

```text
$SNAP/evidence/
  manifest.json          # commit、DB、端口、账号、夹具清单、创建与清理方式
  cases.jsonl            # 每行一个用例结果
  screenshots/
  downloads/
  sanitized-http/
  observations.md
  summary.md
```

## 七、缺陷分级与退出门禁

| 等级 | 定义 | 处理 |
| --- | --- | --- |
| P0 | 越权/身份串写、不可恢复数据损坏、核心流程大面积不可用 | 立即停止受影响用例、保存现场 |
| P1 | 主教学链阻断、统计结果实质错误、静默数据丢失、合法重要场景失败 | 修复前不得作课堂就绪结论 |
| P2 | 可绕过的业务/交互缺陷、重要可理解性或布局问题 | 记录绕过方式并排期 |
| P3 | 轻微一致性、文案、非阻断体验建议 | 记录即可 |

**退出门禁**

1. 全部 P0 用例通过；P1 用例通过或有明确接受者与绕过路径。
2. 统计域（DG-N）每条期望值都有独立 oracle 证据，不使用生产函数自对账。
3. 权限域（DG-P）零越权、零会话串号。
4. 生命周期域（DG-L）零活动资源误删、级联行为与契约一致。
5. 容量与恢复域（DG-K）给出原始测量数据与恢复对账记录，不以“通过/失败”二字代替数据。
6. 门禁全绿；skip 与已接受依赖公告逐条解释。
7. 每个 FAIL 附最小可复现夹具与脱敏证据；BLOCKED/NOT_RUN 不计入通过。
8. 收尾清理：故障注入、临时进程、一次性数据库与目录；确认未被本轮的既有实例与远程演示站未受影响。

```text
D0  环境从零重建（快照/库/账号/总体生成器）        0.5 人日  ── 门禁：DG-O-01 通过
```

## 十、明确不做

- 移动端与响应式布局（产品定位为桌面端；窄视口只记录为已知限制）。
- 真实受限数据的处理（产品边界为合成数据；如需，先做字段级披露控制，属独立需求）。
- 真实反向代理/TLS/HSTS 配置（由部署环境负责）。
- 性能目标之外的容量外推：本轮只给出在**指定硬件**上的实测值，不外推为产品承诺。
- 对既有 dogfood 记录的缺陷清单做逐条复跑；仅允许作为事后交叉核对。
