## 一、目标与组织方式

不是只检查“按钮能点、API 返回 200”，而是验证：

1. 从空白系统开始，教师、学生、管理员能不借助数据库修补完成教学。
2. 研究目标、规划参数、实际抽样、统计结果、提交快照、评分、导出之间语义及数值一致。
3. 网络异常、刷新、身份变化、并发操作不会错账号写入、覆盖草稿或产生虚假成功。
4. 在目标课堂负载下可用、错误可恢复，数据库与附件能成套恢复。
5. 信息呈现有教学解释，键盘可操作，不通过隐藏技术细节制造错误统计直觉。

建议 **6 轮，约 6–9 人日**，不是固定工期承诺。先 R1，再 R2/R3，随后 R4/R5，最后 R6；发现 P0/P1 立即暂停受影响流程，修复并复测后继续。R2 的只读统计核验可与 R3 的隔离账号测试并行；不要并行修改同一模板、任务或学生。

角色视角：新手教师、新手学生、需要重做的学生、批改教师、管理员、维护人员。测试执行可以由同一人分时扮演，但账号、浏览器 session、操作意图须分离。

## 二、执行纪律及证据

- 浏览器使用 **agent-browser**，每角色独立 session。跨标签测试用同一个 session 的多个 tab，跨浏览器用不同 session，不能混淆两者。
- R1 核心建课/学习/提交/批改必须使用实际页面控件；API 只做只读断言。若不得不使用写 API，记录缺口，该用例不能标记纯 UI 通过。
- R2/R3/R4 可通过已授权的真实 API 准备夹具和构造恶意参数；数据库只读核对，禁止改库把失败流程“修通”。需要专项竞态时另建临时夹具并记录。
- 只用合成数据。每轮命名 `DF-Rn-日期-序号`，维护 manifest：账号、班级、模板、任务、实验、文件路径、seed、创建与清理方式。
- 不复用 R0 的已批改学生做破坏性修改；复制模板、新建学生或恢复到另一个库。不能 reset 现有实例或旧项目库。
- 首选桌面 1440×900、1280×800、1920×1080；覆盖浏览器缩放 100%/125%/200%。移动端不属于当前产品承诺，单独记观察，不当成既定交付阻断。
- 故障注入前先保留草稿/服务器状态快照；记录注入/解除时间，结束后删除网络拦截规则、关闭测试 session。
- 每用例记录：ID、版本、角色、URL、前置数据、步骤、预期、实际、状态（PASS/FAIL/BLOCKED/NOT_RUN）、截图路径、控制台/HTTP 错误、只读数据断言、复现频率。
- 截图使用 agent-browser，拍到稳定状态后人工查看；下载文件检查内容和类型，不以“出现下载按钮”为通过。
- API 证据不得包含 Cookie、会话 token、密码；截图避免密码框显明或个人敏感数据。

建议证据目录：

```text
$ROOT/evidence/R1/
  manifest.json
  cases.jsonl
  screenshots/
  downloads/
  sanitized-http/
  observations.md
  summary.md
```

`cases.jsonl` 每行建议字段：`id, commit, role, dataset, status, expected, actual, evidence, issueId, testedAt`。统计覆盖率时 BLOCKED 和 NOT_RUN 均不得计入通过；重试前的失败记录不得覆盖。

## 三、数据与状态矩阵

每项数据至少经过上传、目标映射、规划、抽样、分析、导出链路；不必笛卡尔积遍历全部组合，使用风险驱动组合，并标出缺口。

| 数据族 | 核心场景 |
|---|---|
| 均值 | 正值、包含负值、均值接近/等于零但方差为正、常数列应拒绝、极小/极大数量级 |
| 比例 | 明确类别、类别不存在、稀有类别、0%/100%、类别空白/Unicode 归一化 |
| 系统抽样 | N 能/不能被 n 整除、n=1/n=N、排序与周期性总体 |
| PPS | 相等规模、强偏斜规模、必入单位、规模与目标无关、无有效规模字段、非法零/负/缺失规模 |
| 分层 | 平衡/极不平衡层、单单位层、层数超过预算、层内方差零、比例/等额/奈曼与回灌 |
| 文件 | CSV/XLSX、中文/BOM、长表头、重复表头、公式字符串、缺失值、格式伪装、大小及 10 万行边界 |
| 任务 | 草稿、未开放、开放、截止、延长、跨班、模板已锁定 |
| 实验 | 未开始、阶段 1–4、提交、评分、驳回、重开、旧版本冲突 |
| 账号 | 三角色、启用/停用、重置/改密、班级转移、同角色换账号 |

先使用 seed 的四套总体；新增小规模人工可算数据及接近容量上限的数据，保持独立 manifest，不修改 seed 原文件。

## 五、R2：统计正确性与教学语义（1–2 人日）

环境：dogfood `6465` 的新复制模板；小总体独立核验脚本另写在本轮证据目录，**不得引用生产计算函数作 oracle**。

| ID | 用例及关键断言 |
|---|---|
| R2-01 | 手算比例与均值 Cochran → deff → FPC → 无回答邀请数 → N 封顶；不同精度/置信水平，单位和舍入正确 |
| R2-02 | 最终邀请数不同于推荐数、回答率非 100%、封顶；所有猜测反馈/曲线/确认/分析记录显示同一可达精度 |
| R2-03 | 固定小总体遍历 SRS 样本，对照均值及理论设计方差；n=N 方差为 0，n=1 明确指标条件 |
| R2-04 | 系统抽样遍历随机起点区间，核对分数间隔实际恰好抽 n 个且无重复；周期性总体不承诺优于 SRS |
| R2-05 | PPS 独立核验包含概率和为 n、0<π≤1、必入单位、权重 1/π、Hájek 均值；等规模情形及极偏斜规模 |
| R2-06 | PPS 小总体独立枚举/区间积分核验设计 SE；区分估计偏差、SE、RMSE、正态区间覆盖率；数值不足返回不可用而非假零 |
| R2-07 | 分层三分配方式：整数和为 n、每层不超容量、必需层覆盖、回灌；独立核对层权重与均值/比例 |
| R2-08 | 负值、零均值、常数列、缺失、Infinity/NaN、极小方差；合法负值不误拒绝，非法输入失败可解释 |
| R2-09 | 类别比例的百分点与比例值一致；稀有/0%/100%类别；图表截断不改变完整类别空间统计 |
| R2-10 | 规划高级工具：成本、CV、多指标约束和来源快照；调整/刷新/阶段推进后不回退默认值 |
| R2-11 | 预览 50 行、PPS 概率说明 10 行与完整 CSV；完整 n、行内容和概率逐条一致，SPA 不收到服务端重放索引 |
| R2-12 | 重抽及重开上游后，旧指标/图表/报告引用明确失效；提交快照不受新模板副本变化影响 |

数值判定：整数/行集合要求精确；正常量级浮点默认 `abs(a-b) <= max(1e-10, 1e-8*abs(b))`；极端量级先说明误差界，不能为了通过任意放宽。Monte Carlo 只作补充，使用固定种子和预定统计容差，不要求每次置信区间包含真值。

退出门禁：四方法都有独立小总体 oracle；无 NaN/Infinity 泄漏 UI/导出；所有实际差异有设计解释或修复，不将生产算法自对账当作独立验证。

## 八、R5：课堂并发、持久化与恢复（1 人日）

准备 50 个新合成学生，至少两个班级。负载发生器必须是独立客户端进程；不以同事件循环的压测结果推断主线程延迟。

| ID | 用例及关键断言 |
|---|---|
| R5-01 | 1/10/25/50 人同步登录，最多 4 个 Argon2 并发；统计成功率、首次与含重试 P50/P95/P99、429、重试次数 |
| R5-02 | 50 人读取任务并完成阶段写入，教师同时看进度/评分；人数漏斗、状态和保存结果一致 |
| R5-03 | 同一输入与不同输入并发分析，分别冷/热缓存；避免只有去重命中而错误宣称 50 个重计算通过 |
| R5-04 | 四类抽样并发，10 万行及较宽总体，教师同时下载；主线程普通请求延迟、RSS、CPU、队列等待可观测 |
| R5-05 | 达到/超过队列限制，主动取消部分请求；可重试错误、Retry-After、超时包含排队时间，不无限挂起 |
| R5-06 | 混合读写运行 60–120 分钟；记录缓存预热前后、GC 后 RSS、任务数、孤立文件；无持续失控增长 |
| R5-07 | 对专用本轮实例做优雅重启和强制终止；确认已提交写入持久化、未知结果可查询/重试、草稿保留 |
| R5-08 | 停止新实例写入后备份 DB+storage；恢复至全新库/空目录/新端口，检查迁移、全部引用文件 hash、典型下载、提交快照、成绩 |
| R5-09 | 应用侧模拟数据库连接/磁盘写入失败；不停止主机共享 PostgreSQL、不填满宿主机；请求失败无半成品引用，故障解除后恢复 |

建议首轮验收目标（待在目标教学机复测后确认，并非当前性能承诺）：

- 50 人登录含退避重试 P95 ≤ 15 秒；普通任务/进度读取 P95 ≤ 1 秒。
- 标准教学总体分析 P95 ≤ 10 秒；接纳的请求在 30 秒期限内给成功或可重试响应，不让连接无限挂起。
- 正常 50 人负载无非预期 5xx、无丢写；超容量实验允许明确 429/503，但必须能恢复，单独统计不能藏入成功率。
- 内存记录峰值、稳态及回收后值；预留至少 30% 主机余量。不能仅凭一张 RSS 截图判断泄漏。
- 恢复演练目标 RPO=备份点、RTO≤30 分钟，记录实际时间及数据/文件对账，不以校验和成功代替恢复成功。

## 十、缺陷等级与发布门禁

- **P0**：越权/身份串写、不可恢复数据损坏、大面积核心流程不可用。立即停止受影响测试，保存现场。
- **P1**：主教学链阻断、统计结果实质错误、静默草稿丢失、合法重要场景失败。修复前不作课堂就绪结论。
- **P2**：可绕过的业务/交互缺陷、重要可理解性或布局问题。记录绕过方式并排期。
- **P3**：轻微一致性、文案、非阻断体验建议。

最终门禁：

1. P0/P1 为零；P2 必须有明确接受者、理由及绕过路径，不能默认接受。
2. R1 主链、R2 四算法独立核验、R3 草稿/身份、R4 资源归属、R5 恢复均实际通过。
3. 类型/样式/单测正常与随机/生产构建/迁移检查/原始与适用性审计/数据库集成/教学脚本全部重新执行，准确解释 skip/已接受公告。
4. 保存提交与导出对账、压力原始数据、恢复记录、截图；每用例有状态，不用“全面通过”掩盖未测项。
5. 清理临时网络拦截与一次性测试进程；保留可复现数据和安全基线备份，确认常驻 clean/dogfood 服务及旧环境未受影响。

交付物：每轮 summary、cases、manifest、缺陷列表；最终 `FINAL-REPORT.md` 给出“可内网上课 / 有条件可用 / 暂不建议”的结论及证据，而不是只给通过率。
