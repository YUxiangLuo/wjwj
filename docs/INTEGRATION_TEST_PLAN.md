# 联动测试计划（三轮）

目标：在**重新部署后的开发服务器**上，用真实 HTTP 调用（脚本）与真实浏览器（agent-browser 截图）
跑通"管理员 → 教师 → 学生 → 教师批改 → 学生回看 → 管理员统计"的跨端链路，并记录全部问题。

与前几轮 dogfood 的区别：dogfood 按单端逐条走查；联动测试关注**跨端状态传递**（一端写入后另一端的
可见性/计数/门槛是否随之变化）与**并发、角色隔离、删除护栏**这类只有多端同时参与才会暴露的问题。

## 环境与前置

| 项 | 值 |
| --- | --- |
| 服务 | `bun --hot src/index.ts`，`http://127.0.0.1:3100`（部署方式见下方"重部署步骤"） |
| 数据库 | 开发库 `wjwj_local_dev`，seed 后基线：1 管理员 / 3 教师 / 4 班级 / 20 学生 / 5 模板 / 6 任务 / 17 实验 |

重部署步骤（每次测试前执行）：

```bash
pkill -f "bun --hot src/index.ts"; sleep 2
setsid bash -c 'exec bun --hot src/index.ts > /tmp/wj-dev.log 2>&1' < /dev/null &
# 等待日志出现 Server running，并确认三端登录页 200
```

脚本（仓库内，可重复执行）：`scripts/integration/{lib,round1,round2,round3,cleanup,prep-ui}.ts`。
证据目录（已 gitignore）：`test-results/integration-2026-09-11/`（`round*.json` 结果、`shots/` 截图、`REPORT.md`）。

```bash
bun scripts/integration/round1.ts   # 主链路
bun scripts/integration/round2.ts   # 边界与降级
bun scripts/integration/round3.ts   # 并发、隔离与护栏
bun scripts/integration/cleanup.ts  # 清理测试数据
bun run db:seed:check
```

## 第一轮：主链路贯通（新账号全程）

新教师（管理员创建）+ 新班级 + 新学生（教师导入），从零走完"建课 → 发布任务 → 学生实验 →
提交 → 批改 → 学生回看 → 导出"，检查每一跳的**跨端可见性**。

| # | 步骤 | 期望 |
| --- | --- | --- |
| R1-1 | 管理员建教师 T9xx、建学期/班级并指派该教师 | 教师可用工号登录（默认密码=工号） |
| R1-2 | 教师导入学生（含一条重复学号与一条他人班级学号） | 分类正确：本班跳过 / 他班点名，不泄露他人信息 |
| R1-3 | 教师上传总体→映射→权重→策略→发布模板 | 发布成功；策略按数据实测自动给出（无合格 PPS 则"不适用"） |
| R1-4 | 教师向本班发布任务（截止时间 +5 天） | 班级学生对任务大厅立即可见 |
| R1-5 | 学生完成阶段 1–4 并提交 | 提交成功；教师进度 submitted+1 |
| R1-6 | 管理员发布公告（全体） | 教师端与学生端均能看到同一公告 |
| R1-7 | 教师批改（两步确认）该份提交 | 学生端成绩/评语可见；进度 graded+1；重复批改被拒 |
| R1-8 | 教师导出成绩（数据接口 + xlsx） | 导出内容与批改分数一致；空结果也能导出表头 |
| R1-9 | 管理员统计 | 教师/班级/学生计数与库内一致 |

## 第二轮：边界与降级联动

同一批账号上验证"策略/数据边界"在两端表现一致，重点是**教师意图未被执行时学生不被卡死、教师可见**。

| # | 步骤 | 期望 |
| --- | --- | --- |
| R2-1 | 旧数据坏策略（改库注入 `pps=required`，总体无合格规模列）发布 | 发布被拒并给出可执行原因 |
| R2-2 | 强制置为已发布（模拟历史数据）后学生做实验 | 简单随机+系统抽样完成后阶段 3 通过；写入"不适用"标记 |
| R2-3 | 教师在任务进度查看 | 出现"有 N 名学生的 PPS 因总体数据不可用而被跳过"及名单 |
| R2-4 | 学生端抽样面板检查被禁方法 | 禁用方法不可操作，直接调接口被拒 `SAMPLING_METHOD_DISABLED` |
| R2-5 | 任务临近截止 → 过期后写入 | 提示截止；写入被拒 `TASK_DEADLINE`；教师延长后学生可继续 |
| R2-6 | 教师驳回 → 学生重做 → 重新提交 → 重新批改 | 驳回理由学生可见；阶段可重开；进度计数在两轮间正确回落与推进 |
| R2-7 | 映射边界：重复学号（大小写/全角差异）、全角与千分位数值、零方差均值列 | 判重忽略大小写与全角；数值两端口径一致；零方差拒绝 |
| R2-8 | 比例目标的类别缺失 / 分层取值超过 20 类 | 分别给出明确拒绝原因 |

## 第三轮：并发、隔离与护栏联动

| # | 步骤 | 期望 |
| --- | --- | --- |
| R3-1 | 同班两名学生同时完成同一阶段 | 一成功一 409 版本冲突；仅一次写入 |
| R3-2 | 同一学生并发提交（重复点击） | 幂等：只产生一份提交 |
| R3-3 | 跨教师访问：T2 读 T1 的任务进度/批改/模板/导出 | 404 或 403，不泄露数据 |
| R3-4 | 跨班级：A 班学生访问 B 班任务 | 404/403 |
| R3-5 | 并发批改同一份提交 | 仅一次成功，另一次版本冲突 |
| R3-6 | 删除护栏：学生删除预览与确认、任务删除预览、教师在用时删除 | 有提交时 409 `SUBMISSIONS_EXIST`；确认后级联；进度随之下降；`TEACHER_IN_USE` |
| R3-7 | 管理员审计与统计 | 批改/删除留痕（脱敏），统计与库内一致 |

## 退出标准

- 每轮脚本输出 `pass/fail` 明细（`round*.json`），失败项在 `REPORT.md` 中给出复现步骤与归因。
- 发现的问题按"代码缺陷 / 测试基建 / 环境 / 文档"分类记录，代码缺陷当场修并有回归测试。
- 结束后开发库恢复到 seed 基线（`bun run db:seed:check`），临时账号/模板/任务清理干净。

## 第四～六轮（按研究内容 / 字段）

同一套链路按**不同研究内容**再跑三轮，脚本位于 `scripts/integration/round-content-{a,b,c}.ts`：

| 轮次 | 研究内容 | 换的字段 | 关注点 |
| --- | --- | --- | --- |
| 内容 A | 比例型（毕业生去向意向） | 目标类别 `直接就业 → 考研`；分层 `学院 → 培养层次`；规模 `求职准备度 → 每周职业准备时长` | 保守比例方差规划、百分点口径、比例估计与设计标准误、类别不存在/未映射字段/高覆盖类别等边界 |
| 内容 B | 均值型换字段（食堂等待时间） | 目标 `等待分钟 → 客流量`；规模 `客流量 → 开放窗口数`（离散） | 方差量级变化后的规划与效率对比、多类别分层、规模字段与目标字段循环的护栏、字段不能同时作分层与其他分类 |
| 内容 C | 小总体（学生每周阅读时长，24 行） | 分层 `学院 → 年级`；无可选规模字段 | 有限总体校正、样本量上界 1～N、取满总体的普查口径、PPS 自动不适用时不得误报"被跳过" |
